# 6.5 Problem lists

Where a deadline's or a file's numbered problems and their done marks are kept, and which code reads and writes them.

## Problem lists

A file's numbered problems and their done marks belong to the file (`problems` on the space file, at most `MAX_FILE_PROBLEMS`, 60). A lesson on files works on its first file's list (`ListOwner::File`). `core::spaces::problem_list` is the one place that decides where a deadline's list is:

| Deadline has | Its list |
|---|---|
| an assignment file in the space | that file's list, shared by every deadline that names the file |
| no assignment file | its own `problems` (problems the learner pasted) |

- Reads go through `problem_list` or `problems_of`; writes through `with_problem_list` (`SpaceStore::save_problems`, used by `post_problems` and `conclude`). Both take a `ListOwner`, a deadline or a file. The lesson's tools and its page reach the list through `services::turns::lesson_problems`.
- Readers outside the store get each deadline with its list filled in as `problems` and files without theirs (`with_problem_lists`): `GET /api/spaces/{id}`, the deadline lists, progress and the reminder. The browser never picks the place.
- A deadline with its own list that gets its first assignment file hands the list to that file when the file has none. When the file has its own list, the deadline keeps its list unused, and it shows again when the assignment file is set to none or leaves the space, so done marks are never lost.
- A changed assignment file shows the new file's list; the old file keeps its own. A removed file takes its list with it.
- Version 13 moved each deadline's list onto its assignment file on read. Two deadlines on one file: the list with more done marks stays, then the longer one.
- Teacher sees them in the `today-context` marker (§5).
