# 6.7 Cheat sheets

How a deadline's cheat sheet is made, kept and shown: the record, the chat that changes it and the studio.

## Cheat sheets

A deadline's page has a Cheat sheet word at the top bar's right, opening its studio (`/space/deadline/<id>/cheat-sheet`). The agent makes the sheet as a real PDF with its own tools (LaTeX suggested); godspeed shows that file as is.

Record: `spaces/<id>/cheat-sheets/<deadlineId>.json` (`store::cheat_sheets`, format 4, removed with its deadline), holding:

- last 5 versions, each a PDF in `<deadlineId>-versions/v<n>.pdf` with page sizes and message that made it, or marked as taken from working folder
- sheet's chat (last 100 messages) and rules
- working folder's name

Pictures and PDFs sent in the chat sit in `<deadlineId>-files/`, named by content. `core::study::cheat_sheet` reads older formats: format 3's prompts become the chat's first messages; an HTML or block sheet (formats 2 and 1) keeps its asks and offers Make it again.

Each chat message is one background job ([5.4](05.4-background-jobs.md), `sheet_reply`, `agent::subagents::cheat_sheet_writer`) in the sheet's folder, whose permission questions show as cards in the sheet's chat, not a chat kind, so lessons, search and extraction never see it. The request carries:

- deadline's topics with readiness and a few facts, and mistakes from practice
- sheet's rules and last 8 messages
- working folder `<godspeed folder>/cheat-sheets/<space> <deadline>/`, where agent keeps its source
- message: learner's words and files, and part of a page they pointed at, picture first

The agent answers in markdown. If it changed the sheet, it sends the new PDF's path and any rules the learner set (`new_rules`). Its instructions: render and look at every page, check each formula against the space's material.

godspeed takes a PDF only from inside the working folder, links resolved (`services::cheat_sheets::cheat_sheet_pdf`). It checks the PDF by bytes (at most 20 MB, 1 to 4 pages, each 2 to 17 inches), then copies it into its data. Opening a sheet also takes the newest PDF in the working folder when newer than the current version (an edit outside godspeed), after the same checks, once per file.

The studio is a canvas (`src/frontend/components/cheat-sheet/`):

- Every kept version's pages are artboards, newest first, drawn by pdf.js (served at `/pdfjs/`, outside `/api`, `server::http::ui`). Both halves, the page's and the worker's, are pdf.js's `legacy` build: its default build calls methods a web view older than 2026 lacks (macOS 15's, an older WebKitGTK), and there it never draws a page.
- The view starts fitted to the newest version and fits it again when its room changes, until the learner pans or zooms. In a canvas under 640 points wide the pages lie one under another at the canvas's width, and the zoom keys sit in a row under it (`stacksPages` in `canvas-model.ts`).
- Each page is drawn whole once, then visible part again at screen resolution once view settles, so it stays sharp at any zoom.
- Point at sheet draws a box on a page; that part goes with next message as a picture.
- The chat is a column on the right once something is asked (`sheet-chat.tsx`), and lies under the sheet where the page is under 768 points wide: rules with a remove button, messages, "Made version N" rows, Stop and Try again. The learner writes in the chat's box, the lesson's box with one key, "Ask (teacher's name)" (`sheetBox` in `sheet-box-model.ts`). Before anything is asked the page is the question alone, over that box.
- Print draws pages at 300 dpi into print-only pictures. On desktop, Show in Finder reveals PDF in working folder (`window.lh.showInFolder`); a browser gets a download link. Print and that button are words at the top bar's right, and the paper size is said after the canvas's keys; the bar's crumb reads "<deadline> › Cheat sheet", the deadline a link back.

In a space's lesson, the top bar's Cheat sheet button docks a sheet beside the lesson (`sheet-dock.tsx`) in the lesson's panel (`DockPanel` in `lesson/lesson-dock.tsx`: resizable, one width for every panel, which panel is open and what it shows kept per lesson, one panel at a time; the Document panel, §7, is the other). It shows the lesson's deadline's sheet, else the space's next one with a sheet, with a picker when several. The docked sheet has no chat: questions go to the teacher in the lesson box.

Each row on a space's Deadlines tab (`GET /api/spaces/<id>/cheat-sheets` says where each deadline's sheet is) opens the studio: "Cheat sheet" when one is made, being made, older or newer, "Make cheat sheet" when there is none.
