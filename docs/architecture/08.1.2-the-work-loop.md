## 8.1 The outside-agent boundary: the work loop

### The work loop

Every model request (lesson turn, background job, extraction run, topic grouping) waits in `engine::bridge` as a work item. If no agent is teaching, work waits.

- Agent takes an item with `wait_for_work`, answers with `respond`.
- Claude Code waits in a background script, `.godspeed/wait-for-work.mjs`, spending no tokens while learner thinks. `CLAUDE.md` and idle, `turn_complete`, `start_lesson` notes point it there.
- A waiter given a lesson id stays on that lesson: takes its turns, plus other lessons' turns no one else waits for, oldest first. So one agent takes turns between lessons; two agents each keep their own.
- Codex has no waiter; its wait is capped by its MCP tool timeout (60 s default). Its start command sets `tool_timeout_sec=620` with `-c` flags (`core::spaces::agent_folder`).
- `wait_for_work` takes `timeout_seconds` 1 to 600, default 45.
- Outside lessons learner types to agent in its terminal. When they send a message there ([tauri-shell/terminals.md](../tauri-shell/terminals.md#while-it-runs)), wait from that terminal, or `respond`'s wait for a follow-up, ends at once with a note to answer them there and wait again. It claims nothing, so a waiting lesson turn goes to next wait. The mark lasts until a wait from that terminal reads it, max 2 minutes. For Claude Code waiter reads it and waits again by itself and agent answers learner beside it, so server instructions and `CLAUDE.md` say only to answer them there.
- **The quiet teacher.** godspeed's own teacher starts with no prompt. When it sits idle and its wait would take something (a lesson turn, or a job the learner asked for), `Bridge::nudge_for_teacher` names it: its terminal reached godspeed, its agent isn't working (a typed line or nudge until its Stop hook, a tool call other than `wait_for_work` since that stop, an item it holds), and no wait runs from that terminal. `services::app::teacher_nudge` looks every 2 s and has the shell type "Your lesson is waiting." or "Your job is waiting." (`ToShell::Nudge`); not again while that line hasn't come through the prompt hook, nor within 90 s. The shell types it, sends Enter only once the agent's input box holds exactly that line (Claude Code's box, Codex's `›` composer), and otherwise takes it out and tries again each second for a minute, never while a question shows. The prompt hook knows the nudge, so it never goes to a lesson page, never names a chat and plays no sound. The same loop runs the catch-up once the teacher's terminal first reaches godspeed. The window counts its own running, checked-in teacher as teaching (`statusFromTerminals`).
- A space or lesson an agent starts from godspeed's teacher terminal (not helper's, not an agent outside godspeed; shell says which terminal is teacher's) opens in window even with Follow off. `start_lesson` from an agent whose wait is under way says its running waiter brings turns, so Claude Code starts no second waiter.
- **Opens.** Such a change is marked `open` in the activity log, and so is every `open_page` call, from any agent ([08.1.3](08.1.3-agent-tools-and-notes.md#opening-a-page)). An open is never merged with an earlier one, so asked twice it opens twice. The window (`teacher-provider.tsx`) goes there with Follow on or off, and the teacher panel steps aside as for a click. While the learner has unsent lesson text, a mock runs or a dialog of theirs is open (`openWaits`; the panel's own Activity list doesn't count), the window stays and keeps the open as a held "Go to" in the pill, shown with Follow on too, until its page is reached, a newer open replaces it or 10 minutes pass (`heldStill`, `GO_OFFER_MS`). Only a click on that Go to, or on a Recent row, leaves held work.

### The helper

"Start Claude Code" and "Start Codex" start the teacher in the godspeed folder. The window calls the helper "Background work" (`HELPER_NAME`); code, start scripts, MCP flag and what the agent reads keep "helper". The helper is a second session told "Start as the helper": the window starts it by itself once the teacher has checked in and `helperWork` (below) is above 0; Settings, Connection has Start background work. Its waiter runs with `--helper` (`wait_for_work` with `helper: true`). `engine::bridge::helper` keeps the two apart.

- A work item is background when its conversation id doesn't start with `chat_`: file reading, graph work, sheets, research, topic grouping.
- An **asked** item is one the learner started from a page (a deadline's Ask, study guide or What it's like: `SubagentRunOptions.asked`, `Bridge::mark_asked`). It goes to the teacher's chat, so the learner sees the work. godspeed's own jobs (file reading, graph work, space checks) go to the helper.
- Helper takes godspeed's own background items, asked items left untaken 20 s (the teacher is busy or gone), and lesson turns only while a teacher compacts, including turn teacher held.
- A teacher's PreCompact hook reports compacting via `/api/mcp/compacting`. A mark that never ends lapses after 10 minutes.
- Teacher takes lesson turns and asked items, and godspeed's own items only once one waited 60 s with no helper here (an agent outside godspeed has no helper the window can start).
- `helperWork` in `/api/mcp-access` counts the untaken items a helper would take now (`Bridge::helper_work_count`). An asked item announces `agent-changed` again once its 20 s pass, so the window looks again.
- A helper is here when it checked in within 3 minutes or holds an item whose claim has not run out. It never counts as teaching.

The window shows who works (`src/frontend/components/work/`): a striped frame around a page being worked on, the live pill in every top bar, and tiles for the teacher (under its name) and Background work under Settings, Connection, under a headline naming the agent (each tile's chip says whether it runs; beside the teacher's open panel, the teacher's tile leaves its chip and line to the panel's head).

The pill (`src/frontend/components/top-bar/live-pill.tsx`, words in `live-pill-model.ts`) says the first live thing in one line, in order: teacher needing an answer, background work needing one, a lesson whose reply came while another page was open, teacher at work, background work, a deadline in its last 24 hours. It leaves out what the page already says: a deadline on Today and on its own page; in a page's own bar it shows only while it has something to say. Click opens the teacher's panel on the agent's screen, or closes it; a need opens the screen that has it; in a page's own bar the pill shows the folded notices (`pillClick`). A click never opens a card holding one key: a lesson whose reply waits and a deadline bring their own Open, and a deadline shown as a tag after the pill opens with a click.

A notice (update, restart, new files, saved rule) hangs from the bar for 12 seconds with its title on the pill, then folds into the pill as a count, which shows the folded notices again when clicked; a notice with its own timer closes by itself instead (`notice-store.ts`). Time stands still while the pointer or keyboard focus is on the panel (a clicked key keeps focus but holds nothing), and after the hold a notice has at least 3 seconds and at most 12 seconds left. A 4 point bar along the panel's foot drains with the time left; it is not drawn after opening from the count, nor under reduced motion.

The teacher is started from its own window, so its tile has no button. A tile shows no chip while its agent isn't running (the top bar says "Teacher is off", by the teacher's name). The helper's tile has a button only when godspeed can't start it by itself (browser, or a teacher started outside godspeed) or after it stopped while the teacher runs.

### The work item

A compact JSON block (conversation, tools, messages), then its instructions and every message text of 1,000 characters or more as plain-text blocks. A long text reads `[text N]` in the JSON, so line breaks, quotes and LaTeX need no escaping.

- A long item is split into pages of max 24,000 UTF-8 bytes (`page_blocks`, `core::session::work_pages`), because agents cut long tool results.
- Agent reads pages 2 and up with `read_work`; `respond` is refused until every page is read.
- Images: waiter saves an item's images as files and lists them as `imageFiles`.

What each agent has seen:

- A later item in same lesson carries only new messages.
- What each agent (by session id) has seen of each lesson is saved in `data/agent-seen.json` (`core::records::agent_seen`, `store::agent_seen`), so a restart or second agent gets right part.
- In a new conversation, instructions and tool schemas agent already got come by reference: `instructionsAsIn` names earlier work item, `toolsAsBefore` lists tools.
- `full_context: true` on `wait_for_work`, or `read_work` with `full: true`, sends everything again.

Forget hook: when Claude Code compacts or the learner runs `/clear`, `.godspeed/forget.mjs` calls `POST /api/mcp/forget` with the session id (`handle_agent_forget`, `server::mcp`); that agent's next item comes in full. If the app is closed, the hook removes the session from `agent-seen.json` itself.
