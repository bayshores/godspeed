## 8.1 The outside-agent boundary: the work loop

### The work loop

Every model request (lesson turn, background job, extraction run, topic grouping) waits in `engine::bridge` as a work item. If no agent is teaching, work waits.

- Agent takes an item with `wait_for_work`, answers with `respond`.
- Claude Code never waits itself: its Stop hook waits after each turn and wakes it with the next item ([Claude Code's wake](#claude-codes-wake)), spending no tokens while learner thinks.
- A wait given a lesson id stays on that lesson: takes its turns, plus other lessons' turns no one else waits for, oldest first. So one agent takes turns between lessons; two agents each keep their own. A wait from the teacher's terminal that names no lesson stays on the lesson its chat taught last (`teacher_chats::last_lesson`), while that lesson is kept.
- Codex has no waiter; its wait is capped by its MCP tool timeout (60 s default). Its start command sets `tool_timeout_sec=620` with `-c` flags (`core::spaces::agent_folder`).
- `wait_for_work` takes `timeout_seconds` 1 to 600, default 45.
- Outside lessons learner types to agent in its terminal. When they send a message there ([tauri-shell/terminals.md](../tauri-shell/terminals.md#while-it-runs)), wait from that terminal, or `respond`'s wait for a follow-up, ends at once with a note to answer them there and wait again. It claims nothing, so a waiting lesson turn goes to next wait. The mark lasts until a wait from that terminal reads it, max 2 minutes. For Claude Code the waiter reads it and waits again by itself while the agent answers the learner, so its notes say to answer them there, then end the turn.
- **The quiet teacher.** godspeed's own teacher starts with no prompt. When it sits idle and its wait would take something (a lesson turn, or a job the learner asked for), `Bridge::nudge_for_teacher` names it: its terminal reached godspeed, its agent isn't working (a typed line or nudge until its Stop hook, a tool call other than `wait_for_work` since that stop, an item it holds), and no wait runs from that terminal. `services::app::teacher_nudge` looks every 2 s and has the shell type "Your lesson is waiting." or "Your job is waiting." (`ToShell::Nudge`); not again while that line hasn't come through the prompt hook, nor within 90 s. The shell types it, sends Enter only once the agent's input box holds exactly that line (Claude Code's box, Codex's `›` composer), and otherwise takes it out and tries again each second for a minute, never while a question shows. The prompt hook knows the nudge, so it never goes to a lesson page, never names a chat and plays no sound. The same loop runs the catch-up once the teacher's terminal first reaches godspeed. The catch-up's lesson pass (`services::turns::agent_catch_up`) runs once for each agent session that waits, so a lesson whose extraction failed is tried again when the next session connects, not only at the next app launch. The window counts its own running, checked-in teacher as teaching (`statusFromTerminals`).
- A space or lesson an agent starts from godspeed's teacher terminal (not helper's, not an agent outside godspeed; shell says which terminal is teacher's) opens in window even with Follow off. `start_lesson` tells a woken Claude Code session to say so in one line and end its turn; any other agent, to wait for the lesson's turns.
- **Opens.** Such a change is marked `open` in the activity log, and so is every `open_page` call, from any agent ([08.1.3](08.1.3-agent-tools-and-notes.md#opening-a-page)). An open is never merged with an earlier one, so asked twice it opens twice. The window (`teacher/use-tour.ts`) goes there with Follow on or off, and the teacher panel steps aside as for a click. While the learner has unsent lesson text, a mock runs or a dialog of theirs is open (`openWaits`; the panel's own Activity list doesn't count), the window stays and keeps the open as a held "Go to" in the strip's peek, shown with Follow on too, until its page is reached, a newer open replaces it or 10 minutes pass (`heldStill`, `GO_OFFER_MS`). Only a click on that Go to, or on a Recent row, leaves held work.

### Claude Code's wake

`.godspeed/claude-settings.json` gives the Stop event a second hook beside `agent-event.mjs`: `.godspeed/wait-for-work.mjs` with `asyncRewake: true` and `timeout: 7260`. Claude Code runs it in the background after every turn.

1. The waiter reads the hook's JSON on stdin for the session id and calls `wait_for_work` in 55 s slices.
2. A work item: it writes the item to stderr (the item's JSON line, its instructions and `[text N]` blocks, `imageFiles`, the page header of a long item) and exits 2. Claude Code hands that text to the agent at once, also in an idle session, as a turn wrapped as "Stop hook blocking error from command ...". `CLAUDE.md` says that wording is the wrapper, not an error.
3. The agent answers with `respond`. A follow-up within `respond`'s 30 s wait comes back inline; `turn_complete` says to end the turn with only the word "Waiting.", and that turn's Stop starts the next waiter. One fixed word, for two reasons: Claude Code asks a turn that ends with no words for some (one more model call), and a line about the lesson written before the learner answers reads as a claim about that answer on the next turn.
4. Nothing in 2 hours (just under the hook's timeout), or godspeed says the terminal was closed: it exits 0 and says nothing. The quiet-teacher nudge ("Your lesson is waiting.") gives the agent a turn, whose Stop starts a new waiter.

| Case | What happens |
|---|---|
| A turn ends while a waiter still waits (the learner typed to the agent meanwhile) | Every Stop starts a hook process, and Claude Code does not merge them. Each waiter takes a lock file per session (`godspeed-waiters/<session>.pid` in the temp folder); one that finds a live pid in it exits 0, so a session has one waiter. A lock left by a killed waiter, or older than the hook's timeout, is taken over. |
| A turn ends without answering the item it holds | The agent gets its own item back at once one time (`taken_back`: the turn was interrupted, or it answered in its terminal), and again after it lost its context (`agent_forgot`: compacted or cleared). After that only once the 10-minute claim runs out, as anyone does (`claimable`, `engine::bridge::work`). So the waiter never wakes it with the same item again and again. |
| A woken session calls `wait_for_work` itself | It is answered at once (`wait_of`, `server::mcp::work`): an item if one waits, else the note to end its turn. Its waiter does the waiting, at no model cost. |
| The wake reaches the typed-line hook | Claude Code runs UserPromptSubmit for the wake too, with a prompt that starts `<task-notification>`. `typed.mjs` leaves it alone, so a wake is never offered to the page on screen as a line the learner typed. |
| The learner interrupts a turn | Claude Code fires no Stop then. The next line the learner sends makes a turn whose Stop starts the waiter; with none, the nudge does. |
| godspeed unreachable for over 5 minutes, its token missing, a refusal | The waiter writes the message to stderr and exits 2 once; the agent tells the learner. It keeps the message in `godspeed-waiters/<session>.failed`, so the waiter the reporting turn starts exits 0 on the same failure instead of waking the agent again. Any answer from godspeed removes the file. |
| A session started without the folder's settings (plain `claude` in the folder) | No hook wakes it. The settings set `GODSPEED_WAKES=1`, and the connector marks such a session's `initialize` and calls `godspeed/wakes`; a session without it gets the instructions and notes any MCP client gets ("Call wait_for_work again"), so it still works by waiting itself. |
| A chat from an older godspeed runs the waiter itself | With no hook input it prints "godspeed was updated. Close this window and open your agent from godspeed again." and exits 1. |

### The helper

"Start Claude Code" and "Start Codex" start the teacher in the godspeed folder. The window calls the helper "Background work" (`HELPER_NAME`); code, start scripts, MCP flag and what the agent reads keep "helper". The helper is a second session told "Start as the helper": the window starts it by itself once the teacher has checked in and `helperWork` (below) is above 0; Settings, Connection has Start background work. Its Claude Code start script sets `GODSPEED_HELPER=1`, so its waiter waits with `helper: true` (Codex passes it on each `wait_for_work`). `engine::bridge::helper` keeps the two apart.

- A work item is background when its conversation id doesn't start with `chat_`: file reading, graph work, sheets, research, topic grouping.
- An **asked** item is one the learner started from a page (a deadline's Ask, study guide or What it's like: `SubagentRunOptions.asked`, `Bridge::mark_asked`). It goes to the teacher's chat, so the learner sees the work. godspeed's own jobs (file reading, graph work, space checks) go to the helper.
- Helper takes godspeed's own background items, asked items left untaken 20 s (the teacher is busy or gone), and lesson turns only while a teacher compacts, including turn teacher held.
- A teacher's PreCompact hook reports compacting via `/api/mcp/compacting`. A mark that never ends lapses after 10 minutes.
- Teacher takes lesson turns and asked items, and godspeed's own items only once one waited 60 s with no helper here (an agent outside godspeed has no helper the window can start).
- `helperWork` in `/api/mcp-access` counts the untaken items a helper would take now (`Bridge::helper_work_count`). An asked item announces `agent-changed` again once its 20 s pass, so the window looks again.
- A helper is here when it checked in within 3 minutes or holds an item whose claim has not run out. It never counts as teaching.

### The strip

The window shows who works (`src/frontend/components/work/`): a striped frame around a page while an agent changes it (a space page, a deadline, a cheat sheet; a lesson whose facts are saved has none, since the strip says so and its page does not change; work that waits for an agent has no frame: the strip's status row says "Waiting for <teacher>"), the strip on every page, and tiles for the teacher (under its name) and Background work under Settings, Connection, under a headline naming the agent (each tile's chip says whether it runs; beside the teacher's open panel, the teacher's tile leaves its chip and line to the panel's head).

The strip (`src/frontend/components/strip/`) is 28 points wide (`--lh-strip`), runs down the window's right edge under the top bar on every page inside the app shell (a mock exam too), and is made of the top bar's dark. It is the teacher's panel at its narrowest: the page ends where it starts. The top bar has no teacher control. From the top:

| Part | What it shows |
|---|---|
| Square | Breathes while the teacher works, still while it is on, hollow while it is off |
| Name | The teacher's name, set down the strip |
| Arrow | Points at the page; outside a lesson it steps at the page once every 4 seconds; under the pointer the strip leans 6 points toward the page and the arrow keeps stepping that way. With reduced motion nothing steps, leans or slides |
| Marks, at its foot, only while they have something to say | On the highlighter, "needs you" (an agent's screen waits for the learner: the teacher's first, then background work's) or "your turn" (a reply waits in another lesson); the folded notices as a count; a deadline in its last 24 hours as a countdown (not on Home, not on that deadline's own page) |

The peek (`peek-sheet.tsx`, `peek-store.ts`) is a sheet that slides out of the strip's top, under the bar and over the page, up to 400 points wide. It comes out when the pointer rests 300 ms on the strip or keyboard focus is on it, and tucks back 250 ms after the pointer left both, at once on a press of the strip, on Esc, on a click on the page and on a page change. The strip's marks hide while it is out. Its rows, in order:

1. The teacher's status line (`teacherHead` in `teacher-panel.tsx`, the same words as the panel's head: "Teacher is off", "Waiting for <teacher>", what the teacher does now); lit while the teacher needs the learner. A click does what a click on the strip does.
2. "Background work needs you", lit, which shows that screen.
3. Each lesson whose reply waits: its title, "your turn" and an Open key.
4. Background work under way, by what it does ("Reading 06_Counting.pdf") with its count ("3 of 12").
5. The "Go to Files" key while the teacher changed another page and Follow is off or held.
6. "2 notices", which shows the folded notices under the rows.
7. A deadline in its last 24 hours: its name and countdown, which open the deadline (plain words on the lesson that works on it).

A click on the strip shows the screen of an agent that needs the learner (`showTerminal`, so the terminal window comes forward while popped out); else opens the teacher's panel (`setPanelOpen`: on the teacher's screen, or on Activity alone while that screen is popped out into its own window), which slides out of the strip and docks left of it; else closes the open panel (`stripClick`). Beside the open panel the strip is the arrow, now pointing back at the edge, and the marks alone, and the peek lists only what the panel's head does not say. Follow itself is a key in the panel's head ("Following", "Follow"). The page's room is the window less the strip and the docked panel (`panelLayout`, `--lh-page-side`, `--lh-title`); a lesson plugin's window keeps clear of the strip.

A notice (update, restart, new files, saved rule, quiet space) shows in the peek's sheet by itself for 12 seconds with its own title and close key, then folds into the strip's count; a notice with its own timer closes by itself instead (`notice-store.ts`). While the teacher's panel is open no notice shows by itself: it waits folded in the count. Time stands still while the pointer or keyboard focus is on the sheet (a clicked key keeps focus but holds nothing), and after the hold a notice has at least 3 seconds and at most 12 seconds left. With no strip on screen (the first steps) the sheet floats in the window's top right corner.

The teacher is started from its own window, so its tile has no button. A tile shows no chip while its agent isn't running (the strip's status row says "Teacher is off", by the teacher's name). The helper's tile has a button only when godspeed can't start it by itself (browser, or a teacher started outside godspeed) or after it stopped while the teacher runs.

### The work item

A compact JSON block (conversation, tools, messages), then its instructions and every message text of 1,000 characters or more as plain-text blocks. A long text reads `[text N]` in the JSON, so line breaks, quotes and LaTeX need no escaping.

- A long item is split into pages of max 24,000 UTF-8 bytes (`page_blocks`, `core::session::work_pages`), because agents cut long tool results.
- Agent reads pages 2 and up with `read_work`; `respond` is refused until every page is read.
- Images: waiter saves an item's images as files and lists them as `imageFiles`.
- A lesson item that carries no instructions ends with one more plain-text block: "His rules, every turn (they win):", one "- " line per rule the learner saved for this lesson (the same rules `learner_rules_section` puts at the end of the instructions), then "One idea per reply, at most four short lines, then his move." With no saved rules only that last line is sent. A background task gets none (`every_turn_rules`, `core::records::teaching_areas`; `every_turn_rules_for`, `services::turns`).

What each agent has seen:

- A later item in same lesson carries only new messages.
- What each agent (by session id) has seen of each lesson is saved in `data/agent-seen.json` (`core::records::agent_seen`, `store::agent_seen`), so a restart or second agent gets right part.
- In a new conversation, instructions and tool schemas agent already got come by reference: `instructionsAsIn` names earlier work item, `toolsAsBefore` lists tools.
- `full_context: true` on `wait_for_work`, or `read_work` with `full: true`, sends everything again.

Forget hook: when Claude Code compacts or the learner runs `/clear`, `.godspeed/forget.mjs` calls `POST /api/mcp/forget` with the session id (`handle_agent_forget`, `server::mcp`); that agent's next item comes in full. If the app is closed, the hook removes the session from `agent-seen.json` itself.
