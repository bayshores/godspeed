# 6.4 Source marks and page pieces

How the teacher's source marks are written and checked, and how a problem taken from a space PDF is shown as the real piece of its page.

## Source marks

The teacher marks what it read with a source mark right after the sentence:

- `[[f_1a2b3c4d5e6f:7]]`: a passage id from `search_space_files` or `read_passage`
- `[[https://example.com/page]]`: a web page

Prompt part: `crates/agent/prompts/shared/13-source-marks.md`.

`respond` checks every mark before the reply is stored (`services::spaces::citations`):

- A mark whose passage exists is stored as `[[<file id>/<range>/<file name>]]`, for example `[[f_1a2b3c4d5e6f/p. 12/Week 6 slides.pdf]]`, which still points right after passages are renumbered.
- A mark whose passage doesn't exist is removed, and `respond` tells agent which.
- Web marks are stored as written.
- Cheat sheet replies are checked same way. A reply with a bad mark goes back to agent; a quote that does not hold is dropped there without a word.

A mark may quote a few words: `[[f_1a2b3c4d5e6f:7 "degree 12"]]` is stored as `[[f_1a2b3c4d5e6f/p. 14/Lecture 6.pdf|degree 12]]`. The quote is kept only when all hold (`core::messages::quote_find`):

- 2 or more words, or one code expression
- max 80 characters, no `[`, `]`, backticks or `$`
- found exactly once in passage, ignoring spacing, line-end word splits, ligatures and curly quotes

Otherwise the quote is dropped, the plain mark stays, and `respond` says why. In `topic_done`'s `opener.lead`, a bad quote refuses the call.

In a Study lesson, `respond` then reads the reply's own words, not its other tool calls, plus a `quiz` question, a `problem` statement and a `topic_done` opener's lead for a curve (`core::study::reply_nudges`, `services::turns::reply_nudges`). A reply is sent back unstored, with the line below, when its words hold:

| Nudge | When | Agent reads |
|---|---|---|
| Curve | a Markdown table of 3 or more data rows and 2 or more columns, every cell a number, not all 0 or 1, and no header cell starting with step, iteration, t, k, n or i (a worked trace); or two lines (or list items) in a row, each a label and a run of 4 or more numbers | "not sent: these rows read as points of one curve. Send `plot` with the rows as `points` and a prediction instead. If the table is not a curve, send the reply again as it is." |
| Question list | 2 or more list items ending with a question mark, outside code | "not sent: a reply holds one question. Keep one, cut the rest; never answer one to make the list shorter. If these are not questions for the learner, send the reply again as it is." While a problem is open, it adds "A problem is open: its parts are already asked; don't list them again." |
| Wall | more than 150 words of plain prose (words outside fenced code, `$$` or `\[` display math and table rows) when the learner's newest input is a message he typed, or an answer graded wrong or "I don't know" (`short_reply_input`; a prediction, a right answer, Next problem, Keep going and the goal that opens the lesson never count) | "not sent: {n} words right after his own message or a miss. One idea in at most four short lines, then his move; give away no more than before. He asked for the full rule or a worked example and it needs the length: send it again as it is." |

A reply that sends a `plot` gets no curve nudge. The curve and question list nudges are sent once a topic (the topic the reply's calls name, else the record's, for a question or statement too; for an opener, the topic it opens), so the same reply sent again is stored. The wall is sent once a learner input: the next reply for that input is stored, however long. Which were sent is kept in memory only: after a restart a topic or an input may get each again.

Each wall send-back writes a `[reply wall]` line to the log with the lesson id and the word count, and the next reply for that input writes one more: "identical", or its word count. These lines measure whether the backstop works.

The window turns stored marks into numbered buttons and a Sources list (`src/frontend/components/citations/`). A file source opens a popup with the PDF page or passage text; a web source opens the page. The popup reads two routes:

| Route | Returns |
|---|---|
| `GET /api/cited/<file id>?range=<range>&quote=<words>` | `{name, range, page, text, marks}`. `page` is PDF page number when file is a PDF on disk and range names a page, else `null`. `passage=<n>` in place of `range` names passage id `<file id>:<n>` an agent prints. 404 when no space has file, or no passage is at that range or id |
| `GET /api/cited/<file id>/page/<n>` | page as `image/png`. Optional `crop=l,t,r,b` (fractions of the page, each 0 to 1, `l < r`, `t < b`), `w=<pixels>` (raised to 480, 720, 960, 1440 or 1920; 960 when left out) and `ink=<6 hex digits>` (paper see-through, print in that color) give a piece of the page; any of them present draws a piece, none gives the page as it is. A bad one is 400. Pieces are cached by file version in a separate cache of 32 MB, oldest out first (`PieceCache`, `services::app::reading_pages`) |

`marks` places the quote, or is `null` without a quote or when it is not found exactly once:

- PDF page: `{kind: "page", boxes: [{x, y, w, h}]}`, one box per line, as fractions of page image from its top left, cached beside page images
- text or code file: `{kind: "lines", first, lines, spans: [{line, start, end}]}`, the 12 lines centred on quote's first line, positions in UTF-16 units
- anything else (.docx, .pptx, transcripts): `{kind: "passage", start, end}`, UTF-16 offsets in `text`

File ids are unique across spaces, so the routes need no space id. Plain-text readers (Markdown export, extraction) get the mark in words, like ` (Week 6 slides.pdf, p. 12)` (`cites_in_words`). The pure parts are in `core::messages::citations`, with a twin in `src/shared/core/citations.ts`; both replay `crates/core/tests/golden/citations_quotes.json`. Marks inside code and math are left alone.

A Study reply's topic is the one its calls name, else the one before it, else the plan's first topic. A topic's page excerpt comes from the first quoted mark in the shown opener's lead, else in the topic's first reply that is not only reads (`core::study::topic_parts`, twin of `src/shared/core/topic-parts.ts`; both replay `crates/core/tests/golden/topic_parts.json`).

## Page pieces

A problem the teacher takes from a space PDF is shown as the real piece of its page. The teacher passes a `source` (`fileId`, `page`, `starts`, optional `ends`) on `problem` (practice and study) and on each `post_problems` item (homework, `fileId` left out means the deadline's assignment file; an item with no `ends` ends where the next item's `starts` begins). Neither `statement` nor `text` is then required.

1. `SpacePages` (`services::turns::problem_pages`, the `ProblemPages` port in `agent::tools::ports`) takes the file from the lesson's own space; it must be a PDF on disk.
2. `Pdf::find_piece` looks for `starts` on the page, and once each on the page before and after. Words not found refuse the call with the page's lines, so the teacher can quote exactly.
3. A scan (a page with no words) is one part with crop `[0,0,1,1]` and the teacher's typed words.
4. The result is `details: {piece, text}`, and the teacher reads the piece's words after the usual line (`agent::tools::problem_piece`).

The piece is `{fileId, parts: [{page, crop, aspect}], labels?, mark?}`, checked and rounded by `check_piece` (`core::spaces::page_piece`), the one check for a piece the server hands out, stores or reads back. A stored homework problem keeps `piece` beside `text` and has no `page`. Homework `problem` takes no `source`: it uses the stored piece, and `part` refuses a label the piece does not have. Code that reads a posed problem's statement takes the argument, else `details.text` (`posed_statement`, `core::session::question_core`). The picture is the `crop`, `w` and `ink` route above.

In the browser `PagePiece` (`components/citations/page-piece.tsx`) draws the parts stacked, each asked from the cited page route with its `crop`, a width step and the theme's body ink (`bodyInk` from the appearance provider). Your turn and the problem's card use it; the cited page strip and dialog ask the same route for the whole page in the theme's ink. A picture that does not load gives way to the piece's words. Where the part the learner is on starts, the piece carries `data-part-current`, the same mark a typed problem's part has: the turn brings that place to the top of the problem's own scroll box (`restOnPart` in `turn-scroll.tsx`), and where that box is not cut the page itself rests on the part (`restingTop`). The `As printed` key sits on the row over the piece with the problem's other keys, so a long piece never scrolls it away.
