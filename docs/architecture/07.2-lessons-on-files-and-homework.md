# 7.2 Lessons on files and homework

How a lesson on files starts and works with its Document panel, and how a homework session posts and walks through an assignment's problems.

## Lessons on files

A lesson on files (`POST /api/chats` with `fileIds`, `start_lesson` with `file_ids`) works from 1 to 8 files of one space, the first one first (`files_lesson`, `services::turns::files_lesson`). The chat record keeps them as `fileIds`, set at birth.

1. The first file is the assignment file of a homework or project deadline that is not done and not past: the start is that deadline's homework lesson, as Work on starts or continues it.
2. Else an unfinished study lesson whose first file is the same goes on. The answer says `continued: true`, so the window sends no first message.
3. Else a new study lesson starts, titled with the first file's name without its extension (`display_name`, `core::contracts::space`). It is tied to a deadline (`deadlineId`) when one is named, or when exactly one deadline that is not done and not past covers every file: one it lists, its assignment file or its about file, never one it leaves out.

Refused with the reason: no such file, files from two spaces, none or more than 8, a file named twice, a closed space, an unknown deadline, a .tex that is a PDF's source (the refusal names the PDF's id).

The progress payload's `fileWork` has one row per file with a problem list, in space order: `problems` (`{ done, total }` of its list) and `lessonId`, the lesson its blocks on the Files page reopen: of the lessons whose first file it is, and the homework lessons of the deadline whose assignment file it is, an unfinished one first, then the newest (`derive_progress::file_work`).

- It opens with the space card and the no-topics note, so the agent writes the plan, then a `[Files]` line naming each file with its id and path, a line naming the .tex and its path for a PDF built from one, and the first file's listed problems with done marks (`files_context_text`, `core::study::homework`). The prompt has the teacher edit the .tex only when the learner asks and never build the PDF.
- The first file's problem list is the lesson's (Problem lists, `06.5-problem-lists.md`). The agent composes `prompts/study/20-files.md` (`AgentKind::StudyFiles`) and has `post_problems`, whose sources must be in the first file; `problem` takes a listed problem's `number`, and one cut from its page needs no statement; `conclude` marks it done on solved or solved with hints. A pick from the plan row works as in homework.
- With problems listed, the plan row and "Your turn" are homework's (`GET /api/chats/{id}/problems`, `lessonProblems`); with none, it is a plan lesson.
- The Document panel. A lesson built on files, and a homework lesson with an assignment file, has "Document" in its top bar while one of its files is a PDF (`GET /api/chats/{id}/documents`, `documents_view` in `services::turns::lesson_problems`: the files, each with its display name, its path and a PDF's page count and first page's shape, and `listFileId`, the file the problem list is printed in, null once it left the space; read by the lesson's loader and again 250 ms after the last `spaces-changed` of a burst, since each read opens the PDFs). It opens the lesson's panel (`DockPanel`, shared with the cheat sheet, one at a time) with the PDF's pages one under another, fit to its width and drawn by the server in the theme's ink (`/api/cited/{file_id}/page/{n}?w&ink`, the width rounded up to the page piece widths for the screen's pixels; a picture loads as it nears the view). The open problem is boxed on its page (its piece's stretches, or its mark on a page with columns; nothing is dimmed), and the panel goes to it when it opens, when the problem changes and on the page key, and stays on it through a resize until the learner scrolls (`document-model.ts`). Its head has a picker of the lesson's PDFs (the first file first) only when there are several, then "Page 3 of 9" for the page in view, and Close. A file that left the space leaves the picker, and the word goes and a remembered open panel closes once no PDF is left. A page that does not load shows the load-failed look with Try again; a PDF that does not open says so, and Try again reads the files again.

The lesson keeps its own plan when files are added to the space later. A mock question gone over with no topic of its own is one weak topic (`FREE_TOPIC_ID`).

A Study session started from a deadline records `deadlineId` (a homework lesson records it too but is not a Study session). So does a topic lesson the teacher starts for a deadline (`start_lesson` with `topic` and `deadline_id`) and a lesson on files tied to it, so one deadline can have several lessons. The deadline's Study button reopens the one last worked in (the latest `updatedAt`, which moves only when a message is saved) while that one is unfinished, and then reads "Continue" instead of "Study" (`core::study::continue_study`, `studyLabel`). A deadline's page lists its lessons under its path once it has two, the one last worked in first (`lessonsFor`, `LessonCard`). On a homework's two keys each names its deadline and an unfinished one adds its count ("Continue studying for Midterm, 1 of 4 topics"). The Study page shows the three soonest deadlines as rows under "Coming up" (`DeadlineRows`), each with the line and days block of a Deadlines row, its progress as blocks, and the short keys ("Study" or "Continue", and "Work on it"); "All <n>" opens the Deadlines tab. A lesson one of those rows continues is not the Study page's Continue suggestion. The progress payload carries it as `continueStudy`. A deadline topic with a topic stop in a Study session on the learner's day carries `finishedToday: true` in the progress payload. The plan (`core::study::deadline_plan`, `deadline-plan.ts`) never puts such a topic on today: it moves to tomorrow, or out of the plan when tomorrow is the due day. When that empties today, Home has nothing planned and the deadline's Study button takes all its topics.

## Homework sessions

A homework session (`kind: "homework"`, `deadlineId` required) works on one homework or project deadline's problems.

- "Work on <name>" starts one or reopens the latest (`POST /api/chats` with `homework: true`, `create_homework` in `services::turns::homework`). The key says "Work on it" wherever it shows, with the whole label on hover. It is the filled key of a homework's or project's two keys (`DeadlineKeys`, `src/frontend/components/deadline/deadline-keys.tsx`) at the end of its deadline page's head sheet and on Progress's next deadline; a Study page row has it after the deadline's Study key, and Home's card has it while it shows the deadline. The grey key before it, "Study" ("Continue" while a Study session is unfinished), is the deadline's Study; it hides once the date has passed. A homework lesson is never the deadline's Study session (`lesson_readout`, `services::graph::progress`), so Study never reopens it.
- It opens with space card and a `homework-context` marker: deadline, its assignment file (`assignmentFileId`), a track record line and problems posted before. The line sorts the deadline's topics with the Study rule (`deadline_topics_for`, `core::study::homework`): "Teach first" for untested topics and weak ones whose latest answer was wrong, "Open right away" for the rest. A deadline with no topics reads "none yet, so every problem is Teach first". The marker is written once, so its lines on a missing assignment file or problem list open with "When this lesson started:".
- Homework agent (`agent::tools::homework`, prompt `prompts/homework/` plus practice hint rules) posts assignment's problems with `post_problems`, onto the deadline's problem list (Problem lists, `06.5-problem-lists.md`). An item may carry a `source` instead of its `text`: the problem is then kept as a piece of the assignment's page (Page pieces, `06.4-source-marks-and-page-pieces.md`).
- It opens one problem at a time with `problem`, which has no solution field (homework is hints only) and takes `options` and `multiSelect` like any choice problem (§5). `conclude` marks a problem done when learner's own work is right.
- Before any problem whose idea is under Teach first (or in no topic), the first one too, or when he said he can't do it, the teacher works one look-alike problem (the twin) in full once per lesson, one short line per step, names the move it shares with his problem, then opens the problem in the same reply (`prompts/homework/00-base.md`). The twin has the same move and a different count; it is never one that becomes his answer by renaming or plugging in, nor another problem of the same deadline.
- A problem or part opens with one line on what he hands in. A stuck step climbs by misses: the twin's matching line, then the move named in one line, then that step worked on a second case; he always writes his own.
- On the day the deadline is due, every work item of the lesson ends with the time now and the time due, "Now 9:41 PM; due 11:59 PM." (`due_today_line`, `core::study::homework`; `due_today_line_for`, `services::turns`), and the teacher says the time per problem left and offers to move on past it. Asked in the teacher's terminal ("teach me this first"), it teaches the open problem's method and leaves the problem open.
- With no problem open, nothing waiting, the teacher idle, at least one teacher reply and a problem not done, "Your turn" shows the key "Start problem N" (its next state, the same key as practice's "Next problem" and study's "Continue"; at a stop it keeps going). The key sends the `next` input, and the teacher opens the problem.
- Every problem in the plan row is a button (`problemListRow`, `src/frontend/components/lesson/plan-row-model.ts`). A pick sends the `open` input with the problem's number, done or not; the key reads "Start problem N" and a screen reader hears "Opening problem N". The server saves a `practice-next` marker with the number (`new_open_problem_message`) and refuses a number the lesson's list doesn't have, a pick while a question waits, and the problem already open. The teacher closes an open problem as moved on and opens the pick; a problem closed for a pick makes no long-problem stop (`picked_problem`, `core::study::homework`). A done problem opened again keeps its done mark and shows open with its check. The open problem's cell puts the cursor in the work box. While the teacher writes or a question waits, the other cells stay focusable and say why ("The teacher is writing.", "Waiting for Teacher" by the teacher's name, "Answer the question first.").
- The open problem shows the part the teacher marked whole and folds every other part to one line: its first block, cut to one line by height so math still draws (`partMarks`, `src/frontend/components/lesson/problem-parts.ts`). That line is a button (`aria-expanded`): a click opens the part, a second folds it, and a newly marked part folds them all again. A problem looks the same beside the lesson text and under it. Under the text, in a problem taller than the window, the page rests on the marked part when it sits deep in the problem. The page key, "Page N", sits at the right end of "Your turn"'s title line while the problem shows (`problem-file.tsx`) and opens the Document panel at that page with the problem boxed, in the desktop app and a browser alike; it names the file ("Midterm 2022 key, page 2") only when the problem is printed in a file that is not the lesson's first. A problem in a file that is not a PDF shows the file's name instead, which shows it in its folder on the desktop and is not shown in a browser. No line repeats the deadline name, problem number or file. The open lesson has no head on the page: its title follows the lit space tab in the top bar, and its words sit on the bar's right (`lesson-bar.tsx`, through `top-bar/bar-slots.tsx`). More opens the same lesson menu a Progress row has (`lesson-more.tsx`): Rename, Export as Markdown, Move to another space and Delete. A delete goes to the space's Progress page; a move reads the lesson's record again, so the top bar marks the new space.
- The strip's peek has no Open key for the deadline whose lesson is the open page.
- Plan row names every problem over its bar (`lessonProblems`, `src/shared/core/homework.ts`, over `GET /api/chats/{id}/problems`) once unfolded; folded it says "Problem 2a" and its title with a problem open (no title when it is only the number), or "1 of 14 done" with none open. Home's card says "2 of 7 problems done".

Homework is never extracted into the graph.
