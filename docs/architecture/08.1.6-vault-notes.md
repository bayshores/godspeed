## 8.1 The outside-agent boundary: vault notes

godspeed writes one note per idea the learner worked on into a folder the learner picked: an Obsidian vault, or any other notes folder. The server decides everything except the words; the teacher writes those through two tools. The learner's own notes are only ever read. The story, interface text and pictures are in [vault-notes.md](../design/vault-notes.md); the teacher's block, its cost and the note file are in [vault-notes-backend.md](../design/vault-notes-backend.md).

### Words

"Vault" is a word for code and docs only. The interface says "Obsidian" for a folder Obsidian lists in its `obsidian.json` (or that holds `.obsidian/`), and "Notes folder" for any other (`docs/ui-rules.md`).

| Word | Means |
|---|---|
| Note | A file godspeed wrote, one per space topic. Its `godspeed:` key holds the topic id |
| Your note | A file in the folder without that key. Read, never written |
| Page | What the window shows for a note: `{topicId, name, recall, color, kind, path, saving}`. `kind` is `godspeed`, `kept` (handed over) or `mine` |
| Standing | `topic_status` (§6). In the file it is `confidence`: weak `shaky`, shaky `ok`, strong `solid`, untested empty |

### Where the code is

| Part | Where |
|---|---|
| Pure text: keys, frontmatter, sections, mistake lines, Base file, `obsidian.json`, tool limits | `crates/core/src/vault/`. `note_keys.rs` is the only file that writes the property names; the rest of the app says "space", "deadline" and "standing" |
| Stored record | `crates/store/src/vault_notes.rs`, `data/vault-notes.json` |
| Keyword index of the folder, in memory | `crates/search/src/vault.rs`, filled by `services::vault::index` (at most 5,000 notes, rescanned every minute, only files whose time or size changed) |
| Setting, status, writes, passes, minute check | `crates/services/src/vault/` (`setup`, `write`, `pass`, `maintain`, `search`, `source`, `topic_data`, `notes_list`) |
| The teacher's notes block | `crates/agent/src/vault/notes_block.rs` |
| Lesson tool | `crates/agent/src/tools/vault_note.rs`, `services::vault::lesson_tool` |
| Routes | `crates/server/src/routes/vault.rs` |
| Window | `src/frontend/components/vault/` (owner: `vault-context.tsx`), the Progress card (`overview/notes-card.tsx`), the lesson end (`lesson/end-notes.tsx`), the Settings group (`settings/notes-folder-group.tsx`), the Graph row (`graph/note-row.tsx`) |
| Opening a note | `window.lh.openInObsidian(path)` for an Obsidian folder, else `showInFolder`. Nothing opens in a plain browser, so a page is then not a key |

### Stored data

| Where | What |
|---|---|
| `settings.json` | `vault: { path, words: "teacher" \| "mine" }`, the only home of the path. Changed one field at a time |
| `data/vault-notes.json` | Per space the folder it uses. Per note: topic id, path, the value godspeed last wrote to each key, one hash per section, mistake kinds and ids already written, `state` (`active`, `yours`, `kept`, `removed`), the request waiting for the folder, the skips of its ask. Per lesson: the asks owed and when its answers were last sent |

A damaged record is kept aside, never read as empty and overwritten. A write the disk refuses goes onto the note's record as waiting, with the reason, and is written again by the minute check or by Try again.

### What the window reads

| Route | Answer |
|---|---|
| `GET` and `PATCH /api/vault` | `{folder, words, obsidian, vaults, notes, capped, state, message?, waiting}`. `state` is `none`, `ok`, `missing` or `failed`. `waiting` is `{names, why}` while notes wait, else null; `why` is a line ready to show |
| `POST /api/vault/retry` | The same answer, after the minute check ran now |
| `GET /api/spaces/{id}/vault-notes` | `{notes: [page]}`, the weakest topic first, then by name |
| `GET /api/chats/{id}/vault-notes` | `{pages, asks: [{topicId, name, maxLength}]}`, pages in the order the topics were answered |
| `POST /api/chats/{id}/vault-words` | `{topicId, words}` or `{topicId, skip: true}`, the answer to one ask |

Event `vault-notes-changed` (§10.2) makes every reader read again. `vault-context.tsx` is the one owner of the status; the page lists are read by `use-space-notes.ts` and `use-lesson-notes.ts`, all on `useServerResource`.

### Who computes what

| Thing | Who | How |
|---|---|---|
| Which topics earned a note | Server | Topics with an answer since the last pass, from the lesson readout |
| Standing, answer counts, next review | Server | `topic_status` and `core::study::review`; none until a right answer |
| `test` | Server | Every open deadline whose topics hold this one |
| Mistakes to send | Server | `space_mistakes`, newest first, at most 4 a pass |
| Path and file name | Server | `<folder>/<space folder>/<topic name>.md`, names safe on every OS |
| The space's `.base` file | Server | Written once with the space's first note, filtered by folder, never rewritten |
| Who owns a key or section | Server | `godspeed:` key, last values per key, hash per section (below) |
| Which of the learner's notes may cover a topic | Server proposes (up to 3 from the index), teacher picks | The search has no cutoff |
| Text, recall, mistake wording and kinds, links, source passage | Teacher | `write_vault_note` |

### Passes

A pass sends the answered topics of a lesson to the teacher once, as a notes block. The block is self-contained, so any agent writes it at the same cost.

1. A lesson end, leaving a lesson that has new answers (`PUT /api/talk-page`, `lesson_left`), and an agent's catch-up at start (`catch_up`) queue the lesson.
2. If a helper is running, the block rides in the space's next topic grouping item. A queued pass waits 3 minutes for the grouping, then goes on its own.
3. Otherwise it goes as an item of its own once no lesson turn waits. A helper is never started for notes.
4. After a failed run the same pass is not sent for 10 minutes.
5. The teacher calls `write_vault_note` once per idea. The server writes the file, then tells the window.

The minute check (`scanner.rs` calls `minute_check` and `send_waiting`) does the rest:

| Job | Rule |
|---|---|
| Reread the folder | Index and status |
| Follow a note | Found again by its `godspeed:` key after the learner moved or renamed it |
| Removed notes | Marked removed only when the file is gone, its folder is still there, and it is the only one gone. Several at once mean a moved folder or a sync |
| `godspeed: keep` | A note whose file name is one topic's name gets that topic's id and godspeed's keys. Any other stays for the teacher to match |
| Waiting writes | Written again; one whose topic is gone is dropped with a log line |
| Key refresh | Once a day per space (and after a review the learner answered), the notes are written again with no new words so `confidence`, `next_review` and `test` follow the record |

### Tools

| Tool | Where | Rule |
|---|---|---|
| `write_vault_note` | MCP, and a lesson tool in every lesson started while a folder is picked | Limits in `core::vault::note_tool`: title 80, text 1,200, recall 200, mistake text 160 and kind 30, links 6. Answer `status` is `written`, `updated`, `linked` or `waiting`; `kept` names what was the learner's. Refused with a reason when no folder is picked, the topic is unknown, the space is closed, a link names no note, or the note was removed (only "Note this" makes it again) |
| `search_vault` | MCP only | `{query?, path?, limit (8, max 30), space_id?}`: snippets of 200 characters, or one whole note cut at 20,000. Refused with no folder or a path outside it |

The godspeed folder's `CLAUDE.md` and `AGENTS.md` say the folder is read only with `search_vault` and written only with `write_vault_note`, never with the agent's own file tools. The teacher's list, Learn group, says "Note this", dim with "needs Obsidian or a notes folder" until a folder is picked.

### Who owns what in a note

| Part | Owner |
|---|---|
| `godspeed`, `class`, `test`, `confidence`, `answered`, `mistakes`, `next_review`, `facts`, `up` | godspeed, until the learner changes one; that key is theirs from then on |
| Any other key | The learner, kept byte for byte |
| Recall, "In short", "Related", "Check yourself" | godspeed while the section's hash matches what godspeed last wrote; the learner's once they edit it |
| "Mistakes to remember" | godspeed merges lines while it is its own; once edited, godspeed only adds lines at the end. One line per kind, at most 6 kinds |
| "My words" | The learner, never hashed. Written once from the words typed at a lesson end |

An index scan of a linked folder (§6.1) skips the notes folders and any file with a `godspeed:` key, whose facts are already in the graph. A note of the learner's with `godspeed: keep` is read as an ordinary file until taken over.

### The window

| Part | Behavior |
|---|---|
| Progress card | "Obsidian" (a plain folder: "Notes") with the count and "All"; one row of pages that fit, weakest first, a page still being written dashed. No folder or no notes: no card |
| Lesson end | Under "That was the last topic." the pages land one at a time; one being written is dashed with a bar at its foot. Under them "Saving to Obsidian", then "Saved to Obsidian". In the short pinned sheet the row scrolls sideways |
| "My words" asks | With `words: "mine"`, at most 3 asks per lesson end (`ASKS_MAX`), one at a time, the most answered first. The head says "My words", the asked page is outlined, and Done for today, Skip and Save sit in the box (Save is the main key). A topic skipped twice is never asked again |
| Failure notice | `NoticeCard` in the strip: "Couldn't save A and B to Obsidian." (more than 2: "A, B and 3 more"), the reason, and "Try again", or "Settings" when the folder is gone |
| Graph | The topic panel ends its list with one row, "Open in Obsidian" (a plain folder: "Show in Finder"), when the topic has a note |
| Settings | General, group "Obsidian" or "Notes folder": the folder's name and line, Open, Unlink, and "Who writes the note" |
