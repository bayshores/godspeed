## 8.1 The outside-agent boundary: tools, notes and web search

### The other tools

Besides the loop, agents get lesson, graph and space tools (`crates/server/src/mcp/tools.json`):

- `list_lessons`: `space_id` (a space or `"none"`), `limit` (default 20, max 200); returns `{lessons, total}`.
- `search_graph`: `space_id`, `query`, `limit` (default 30, max 200), which caps facts and chains alike. Each fact comes with `from` and `asked` (§6, "The teacher's graph tool"). The lesson tool of the same name runs the same code (`services::graph::graph`) on the lesson's own graph with a limit of 8.
- `read_lesson` pages a long lesson.
- `read_space` gives file counts by status and only failed files; `files: true` lists all. Its deadlines carry their about file. `outOfDate` names the space's unanswered gap ([6.8](06.8-gaps.md)).
- `add_space_deadline` saves a deadline due more than `PAST_ADD_DAYS` (7) days ago as done, with no `doneAt`, and says so in its `note`. The learner's own add is never saved done.
- `add_space_file` takes a `path`, or `name` and `text` (up to 20,000 characters) to write a Markdown file into space. A written file is marked `written` on its entry; a later write by that name replaces only such a file; a name learner's own file has is refused. A `path` inside the godspeed folder's `made/` (`made_path`, `services::app::agent_folder`) is a file the agent built: it is copied in the same way (`add_made_file`), so its next build replaces it and keeps its id, and its entry keeps where the source is (`madeFrom`, from the godspeed folder). A path anywhere else is the learner's file and is copied as a new one each time. `lesson_id` (a lesson of that space) is kept on the entry (`lessonId`). `read_space` with `files: true` lists both.
- `add_space_deadline` takes a `deadlines` list, `set_space_file_kind` a `file_ids` list. Valid items apply; failed ones come back under `refused`.
- `update_space` and `unlink_space_folder` return only what changed.
- `write_vault_note` (also a lesson tool) and `search_vault` (MCP only) write and search the learner's notes folder ([08.1.6](08.1.6-vault-notes.md#tools)).

`start_lesson` takes `topic`, `deadline_id` or both, or `file_ids` (`services::spaces::start_lesson`). A topic starts a new lesson whose title is the learner's first message; with `deadline_id` too, that lesson is for the deadline, in the deadline's space. `file_ids` (1 to 8, never with `topic` or `homework`) starts or continues a lesson on those files as the Study key on a file does (Lessons on files, `07.2-lessons-on-files-and-homework.md`); `deadline_id` with it ties a new one to that deadline. A deadline alone does what its keys do (`services::turns::deadline_lesson`): Study continues the unfinished lesson for it last worked in or starts one on its topics; with `homework: true`, Work on continues its latest homework session or starts one. Continuing at a stop stores Keep going first, as the window does. The answer's `status` is `started` or `continued`; a continued lesson sends no first message, and its note says the learner goes on there. Refused like the window offers no key: a deadline marked done, Study once the due time passed, homework on a deadline that isn't homework or a project, a closed space. A topic with no `deadline_id`, in a space where a deadline due within 2 days has an unfinished lesson, is sent back once (`near_deadline_ask`): the refusal names that lesson and says how to go on with it, how to start the new lesson for that deadline, and that the same call again starts it apart. A lesson started apart from its deadline has none of that deadline's record.

Every tool states all four MCP hints (read-only, destructive, idempotent, open world).

### Opening a page

`open_page` opens a page in the learner's window when they ask to see something: Home, a space's Progress (which holds its lessons), Files, Deadlines or Graph, a deadline, its cheat sheet, or a lesson (`services::app::open_page`). Lessons of every kind and the cheat sheet's agent have the same tool (`LessonSide::open_page`, the sheet request's lookups), so "open my cheat sheet" works mid-lesson too.

- `page_for` checks the ids and gives the path, the space and the item Follow lights (the space's tab, always shown; none for Home). It refuses an unknown space, deadline or lesson, a closed space, Files or Deadlines with no space, and an interview's cheat sheet (interviews have none).
- The call records an activity entry marked `open` (see [Opening a page from the terminal](08.1.2-the-teachers-round-and-the-strip.md#opening-a-page-from-the-terminal)) and sends the shell `ToShell::ShowWindow` ([tauri-shell/the-main-window.md](../tauri-shell/the-main-window.md#menu)).
- The window says which page and space it shows in the same report that names its talk page (`PUT /api/talk-page`, `use-terminal-lines.ts`; cleared on `pagehide`), and `TerminalState::window_page` (`services::app::terminal_state`) keeps it beside the talk page. The answer says the open was sent, or that the learner is already there, or that it opens beside their lesson: a lesson on the same deadline opens the cheat sheet in its panel (`useLessonDock`, `lh:open-sheet`) instead of leaving. A cheat sheet with no PDF yet opens on its page's own "not made yet" state, and the agent is told.

### Agent notes and the briefing

`remember` and `forget` keep short notes about the learner in `data/agent-notes.json` (`store::agent_notes`, max 200 characters each). The learner sees and deletes them in Settings, Teaching, Remembered.

Every `initialize` or `server/discover` hands over instructions in this order:

1. intro: what godspeed is, and that outside lessons the learner types to it in godspeed's terminal, with `open_page` and `start_lesson` for what they ask there
2. "Where you left off" briefing (`services::app::agent_memory`, `core::spaces::agent_briefing`): setup each space still lacks, spaces (each with its unanswered gap, [6.8](06.8-gaps.md)), last lessons (each with the files added for it: "its files: Practice test.pdf"), next deadlines, saved notes
3. Memory and Spaces paragraphs

Texts only agents read (these instructions, prompts in `crates/agent/prompts`, the folder's `CLAUDE.md`, `AGENTS.md` and `.godspeed/setup-spaces.md`, background agents' prompts, tool descriptions, notes tools' returns) are written short to save tokens: no articles or filler, fragments where clear. Each one leading to writing for the learner says to write to the learner in full, plain sentences; rules on the teacher's tone, praise and reading level stay in full sentences.

The setup check (`core::spaces::space_setup`) lists a missing icon, signature or description, so older spaces catch up when an agent next connects. Claude Code cuts server instructions at 4096 characters, so the briefing has a length budget: it drops lessons first, then deadlines, oldest notes, spaces, setup, and says what it left out.

### Talking to the agent outside lessons

Outside lessons the learner types to the agent in its own screen in the teacher panel; the window has no chat of its own there.

An older build's Talk chat (kind `"talk"`, fixed id `chat_talk`, `TALK_CHAT_ID`, its `chat_talk/` folder of PDFs) is the learner's and only ever read:

- Chat store refuses to make, write or delete it (`TALK_KEPT`, `store::chats`): every writer, `delete_chat`, `save_attachment`. `POST /api/chat` to it answers 404 "Talk was replaced by your agent's screen"; `DELETE /api/chats/{id}` answers 404 "No such lesson".
- Store leaves it out of every lesson list, so Home, Progress, search, `list_lessons` and extraction never see it; lesson page 404s for it.
- Its old deadline requests still count as asked (see [Deadline requests](06.1-spaces.md#deadline-requests)).
- On a start with a Talk record and no `data/talk-backup-*` yet, server first (right after taking data lock, before anything else reads record) copies `chat_talk.json` and `chat_talk/` to `data/talk-backup-<version>` (`services::app::old_talk`). Once, into first godspeed folder set up after that, it writes `Talk.md` (who said what, each change one line, math as written; `core::messages::talk_export`) with pictures and PDFs in `Talk files/`. Each picture and PDF is written under a `.partial` name, flushed to disk, renamed; `Talk.md` last; `talkExported` is set only after, so a start cut off halfway makes it again. A `Talk.md` already there with other text is learner's and never changed: export goes beside it under first free name of `Talk (godspeed).md`, `Talk (godspeed) 2.md` and on, with `Talk files (godspeed)/`, `Talk files (godspeed) 2/` and on. The backup's files are flushed to disk before its folder is renamed; neither backup nor export follows a link. A failed export leaves `talkExported` unset, so next start retries.

While a lesson is open, the panel shows only the screen, and its head only the screen's own status (starting, a question, ended): the lesson is the chat, and the strip says what the teacher does and opens the teacher's panel with its screen and Activity, as on every page. Lessons get `list_spaces` and the three deadline tools (`lesson_space_change_tools`), so "add HW 4, due Friday" works mid-lesson.

### Rules the agent saves

When the learner states a lasting preference, the teacher calls `save_rule` (`agent::tools::rules`), or an outside agent calls the same-named MCP tool.

- Rule joins learner's own list (Settings, Teaching for every lesson; Edit space for one space), within usual 20 rules of 200 characters.
- `data/agent-rules.json` (`services::app::agent_rules`) marks it as agent's, so lists say "Saved by" and teacher's name.
- A lesson shows save as one line with Undo and Edit (`rule-saved-line.tsx`). A save from terminal sends `rules-changed` with rule, and window shows a notice in the strip's peek (`rule-notice.tsx`). Both go through `/api/rules`.
- Editing a rule makes it learner's. Marks of rules learner removed are dropped when list is read.

### Web search

By default the outside agent uses its own web search. A learner may save their own Tavily key under Settings, Teaching, Facts and research, below the Web search switch (`services::app::web_search`, `GET /api/web-search`, `PUT` and `DELETE /api/web-search/key`).

- `store::search_key` keeps it in `data/search-key` (mode 0600). The window only ever gets its last 4 characters.
- Sent to `api.tavily.com` alone (`web::tavily`). Saving checks key with Tavily first; page shows searches used this month.
- With a key, research job gets a `web_search` tool (5 results a search).
- `web_fetch` turns a page into markdown with Readability, r.jina.ai as fallback (`crates/web`). `web::guard` refuses an address on this computer or a private network, as written, after every redirect and for every resolved address.
