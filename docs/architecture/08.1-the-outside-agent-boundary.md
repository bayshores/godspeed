## 8.1 The agent boundary

The learner's agent (Claude Code or Codex, on the learner's own plan) is the only model. No model-provider credentials exist anywhere in the app. godspeed runs the agent itself (`gs_runtime`): every lesson, job and teacher panel chat is a session of its own, in the godspeed folder ([5.3](05.3-the-agent-session.md), [8.1.4](08.1.4-how-the-agent-starts.md)), and the agent reaches godspeed's tools only through its session. No other program can reach godspeed: the server answers only the window ([api-protection](../tauri-shell/api-protection.md)).

- Lessons and jobs open their own sessions on the picked agent (`agent-folder.json`), or on Claude Code before a pick. They never wait for a pick ([background jobs](05.4-background-jobs.md)).

- The agent has no on or off state of its own: it runs whenever a lesson, job or chat needs it. While it can't run, the setup card says why ([below](#the-agents-setup)). How many lesson and teacher panel chat turns run now is `GET /api/turns` (`{running}`), which the window reads once (`turns-running.tsx`) and again on `turn-started` and `turn-settled`: Restart asks first while one runs, and Follow says "Working" for a lesson's turn on another page.

### The agent's setup

The setup card reads the server, which asks the agent's own programs and never reads or copies a login (`services::app::agent_health`, `agent_login`, `agent_update` and `agent_models`; the checks themselves in `gs_runtime`).

| Route | What it does |
|---|---|
| `GET /api/agent/health` | The picked agent's checks in the card's order (`installed`, `node` for Claude Code, `upToDate`, `loggedIn`), each `{check, state, fact, problem, reason, needs, link}` with state `passed`, `failed` or `unchecked` (the last four null unless it failed); `failing` (`{check, problem, reason, needs, link}`, the first failure, `helper` last; `needs` is the version a too old agent or Node.js needs, `link` the page "Get it", "Get Node.js", "See plans" or "Reinstall godspeed" opens); `checking`; `ownCommand`; `login`; and `update` (`{state, line, command}` while an update runs or after one failed, else null). The learner's own start command is asked nothing. |
| `POST /api/agent/health` | Checks again now ("Check again", or the window back in front while a check fails) and gives the same view. |
| `POST /api/agent/login` | Starts the sign-in and gives `{url}`. Codex signs in to godspeed's own Codex folder (`account/login/start`); Claude Code runs its own `claude auth login --claudeai` as a child. One at a time: a second start gives the running one's page. |
| `POST /api/agent/login/code` `{code}` | Writes the code Claude Code's sign-in page showed to its input. |
| `POST /api/agent/login/cancel` | Ends the sign-in: Codex's `account/login/cancel`, or Claude Code's child by its own process. |
| `POST /api/agent/update` | Updates the agent the way it was installed and gives `{state, line, command}`: `claude update` for Claude Code; for Codex `npm install -g @openai/codex@latest` when it sits in npm's global folder (`npm root -g`), `brew upgrade codex` when in Homebrew's `Cellar` or `Caskroom`. `command` is also what the learner can run in a terminal. When godspeed can't tell how Codex was installed, the state is `failed` at once with that command. One at a time: a second start gives the running one. 409 with the reason when none can start (the learner's own command, or no agent found). |
| `GET /api/agent/models` | `{agent, models: [{id, name, default}]}`, from Codex's `model/list` or Claude Code through the helper. The model new lessons start on is `model` on `GET /api/agent-folder`. |

A check takes 15 seconds at most and makes no model call. It runs at server start, when the agent or its start command changes, after a sign-in or an update, and when a session cannot start or the agent refuses its sign-in. Each start and end is told with `agent-health`. A sign-in that fails stays on the card until the next one starts or a check finds the agent signed in; Claude Code's ends after 5 minutes.

The window reads the setup once (`agent-setup/agent-setup-context.tsx`): again on `agent-health`, with `agent-update`'s newest state over the read's own, and checked again (`POST /api/agent/health`) when the window comes back to the front while a check fails. A check that runs again for the same agent carries the answer before it, so that answer stays shown until the new one comes (a sign-in that just ended never flashes its Log in key). `agent-card-model.ts` words it; the server decides every state.

| Where | What shows |
|---|---|
| Settings, Teacher; onboarding's step 1 | The full card (`AgentCard`): the agent pick, the Version and Account rows with the key that fixes each, then the model once both pass (`PATCH /api/agent-folder {model}`, null for the agent's own default). Settings adds the teacher's name, the folder and the start command. |
| The teacher's panel while the agent can't run | The compact card in the writing row's place (`teacher/setup-foot.tsx`), with the other agent under it as a plain word ("Use Codex", "Use Claude Code"). "Try asking" waits dim above it, and the head keeps only Activity. Once the agent can run, the line folds away with its last words, the box fades in in its place, and Chats, Follow and Pop out fade back. While the other agent's first check runs, the panel stays as it was; before the window's first check, neither the line nor the box shows. |
| The failure line of a job the learner started: a lesson's error row, the lesson's newest dispatched job, the cheat sheet's failed line, a deadline request's line, the mock page | The compact card (`AgentCompact`, through `JobFailure`) in place of the line, while the agent can't run and the panel is shut: one sentence that names the agent and the failing row's key. Once it can run, the line with its Try again is back. The panel's Activity keeps its rows, since the open panel's foot says it. |
| Onboarding's last step while the agent can't teach | The compact card under "You're almost set." (`onboarding/done-step.tsx`); Start learning still finishes. |
| The strip's peek | Its status row says the compact card's sentence; a click opens the panel, whose foot says it. |

The compact card's sentence names the agent ("Claude Code isn't logged in."). Once Log in was pressed it is "Finish in your browser.", with the code field when Claude Code asks for one, and Open again and Cancel.

An update runs its command as a shell would, in the agent's environment, and `agent-update` tells its start, each line it prints (`running`), and its end: `done` when the command ended with 0 and the agent now says a version at or past the floor, else `failed` with the last line of its error output (or of its output) and the command. It ends by its own process after 10 minutes. Before it runs, the runtime lets go of its cached connection to the agent, since a Codex app-server kept for the next session would run the old program (and on Windows hold its file); sessions open now keep theirs. A done update checks the agent again; a failed one stays on the card until the next update or a check finds the agent new enough.
