## 8.1 The outside-agent boundary

The outside agent is the only model. No model-provider credentials exist anywhere in the app.

### Access

- Server makes access token `data/mcp-token` (mode 0600) on first `/api/boot` and whenever missing (`ensure_mcp_token`).
- `/api/mcp` accepts only local, non-browser requests carrying token (`refuse`, `server::mcp`).
- Godspeed folder's connector finds address in `mcp-endpoint.json` and reads token file itself.
- Settings, Connection: connection status, show and rotate token, button that opens agent or setup for another MCP app.

Server speaks two MCP versions on one endpoint. 2026-07-28 carries client version and name on every request, and `server/discover` replaces the handshake (Claude Code, folder scripts). The older version starts with `initialize` (Codex). Each request names the agent from client info. Both answer plain JSON (`server::mcp::transport`), never SSE, since folder scripts can't read SSE.

### Connected

| Word | What decides it |
|---|---|
| Connected | Any authorized MCP request in the last 3 minutes (`services::app::terminal_state`). Only the terminal's readers use it: the teacher pane's status line says "<teacher> is on", and in the browser the start pair shows while no agent is connected. |

- Lessons and jobs open their own sessions on the picked agent (`agent-folder.json`), or on Claude Code before a pick. They never wait for a pick or a terminal ([background jobs](05.4-background-jobs.md)).
- The window hears `agent-changed` when connected changes, the agent's name changes, or the learner picks an agent. A timer fires it again a second after the next lapse.

`GET /api/mcp-access` reports `agentConnected`, `agentName`, `turnsRunning` (lesson turns running now, which Restart now asks about first), `terminals` (each live app terminal as `{id, here}`; `here` = request from it in last 3 minutes) and `outsideHere` (request with no terminal id in last 3 minutes). The window reads it again on `agent-changed`, `turn-started` and `turn-settled`.

An agent started in a desktop-app terminal sends the terminal's id with every request. Once that terminal ends, the server refuses it ([tauri-shell/terminals.md](../tauri-shell/terminals.md#terminals)). The server's connected still lasts 3 minutes, so in the desktop app the window reads its terminals instead: once godspeed started a teacher, no agent counts as connected until that teacher runs and has checked in, or an agent outside godspeed is here (`statusFromTerminals`). Whether an agent is picked is the server's alone.
