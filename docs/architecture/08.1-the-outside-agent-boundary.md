## 8.1 The outside-agent boundary

The outside agent is the only model. No model-provider credentials exist anywhere in the app.

### Access

- Server makes access token `data/mcp-token` (mode 0600) on first `/api/boot` and whenever missing (`ensure_mcp_token`).
- `/api/mcp` accepts only local, non-browser requests carrying token (`refuse`, `server::mcp`).
- Godspeed folder's connector finds address in `mcp-endpoint.json` and reads token file itself.
- Settings, Connection: connection status, show and rotate token, button that opens agent or setup for another MCP app.

Server speaks two MCP versions on one endpoint. 2026-07-28 carries client version and name on every request, and `server/discover` replaces the handshake (Claude Code, folder scripts). The older version starts with `initialize` (Codex). Each request names the agent from client info. Both answer plain JSON (`server::mcp::transport`), never SSE, since folder scripts can't read SSE.

### Connected and teaching

`engine::bridge::checkin` decides both, 3-minute window.

- **Connected**: any authorized MCP request in last 3 minutes, or teaching.
- **Teaching**: work-loop call (`wait_for_work`, `respond`, `read_work`) by a non-helper agent in last 3 minutes, or a teacher still holding a work item whose 10-minute claim has not run out.
- Connected but not teaching leaves lessons waiting; teacher pane and Teacher tile say to start teaching. godspeed's own teacher is the exception: it starts quiet, the window counts it as teaching, and godspeed nudges it when work waits ([the work loop](08.1.2-the-work-loop.md#the-work-loop)).
- Window hears `agent-changed` when either changes or agent's name changes. A timer fires it again a second after next lapse.

`GET /api/mcp-access` reports `agentConnected`, `agentTeaching`, `agentName`, `helperHere`, `helperCovering`, `pendingWork`, `pendingTurns`, `helperWork` (untaken items a helper would take now), `claimedLessons` (lessons whose request an agent took and hasn't answered), `terminals` (each live app terminal as `{id, here}`; `here` = request from it in last 3 minutes), `outsideHere` (request with no terminal id in last 3 minutes). `wait_for_work` counts as a request on each 15 s slice, so an agent in a long wait stays here.

An agent started in a desktop-app terminal sends the terminal's id with every request. Once that terminal ends, server refuses it and puts back what it claimed at once ([tauri-shell/terminals.md](../tauri-shell/terminals.md#terminals)). Server connected and teaching still last 3 minutes, so in the desktop app the window reads its terminals instead: once godspeed started a teacher, every surface shows no agent and no helper until that teacher runs and has checked in, or an agent outside godspeed is here (`statusFromTerminals`).
