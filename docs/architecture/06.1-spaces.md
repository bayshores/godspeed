## 6.1 Spaces

Each space has its own graph. `graph_store_for(app, scope)` (`services::graph::graph`) gives `data/graph/` for "No space" and `data/spaces/<id>/graph/` for a space. Extraction picks the graph from the source's space, so lessons and files write into their own space's graph. A lesson reads only its own space's graph, and `merge_findings` writes only the source's own graph.

Space code:

- `services::spaces::pipeline`: file pipeline, linked-folder scan every 60 s
- `services::spaces::lifecycle`: space lifecycle, cascade delete
- `services::spaces::space_card`: space card
- `services::turns::lessons`: lesson creation

### Space files

A file is `study` (turned into facts) or `info` (the teacher can read it with `read_space`, `search_space_files` and `read_passage`, but it never becomes facts).

A file the learner adds by hand (Add files, a drop on the Files page, first-run setup) starts as `study`. On a file's first read the agent can say it is logistics (`import_notes` with `may_be_space_info`, decided on first stretch); godspeed then switches it to info (`sortedAsInfo`). Never sorted: a kind set on purpose (`kindChosen`: Move to …, `set_space_file_kind`, and every file the agent adds with `add_space_file` or `import_notes`), and lecture transcripts and recordings.

Supported files:

- plain text (including LaTeX `.tex`) and code, read as is; text files with no extension (checked by bytes)
- PDFs (`crates/pdf`)
- Word and PowerPoint (`crates/files`, `office`, on a small zip reader; slides headed like PDF pages)
- EPUB (`epub`, same zip reader; each spine file is a section headed like a PDF page; copy-protected books and books with no text are refused)
- captions and recordings; recordings are transcribed locally with whisper.cpp (`crates/transcribe`)

The Files page puts its own words in the top bar: Find (by file name), Linked folder or Link a folder, and Add files, before Edit space. Show in Finder stays at the end of the page's head sheet, which has the file count as a block on the space's color and the summary line. Each group is a sheet; a row starts with a tile of the file's type (dark for study material) and ends with its menu key, three dots. A file with a problem list shows its problems in the row's state, as blocks and then "5 of 12 problems done", in place of its facts; a state that needs the learner (Failed, Needs a speech tool, Building facts, Waiting) keeps its words after the blocks. With a lesson on the file, the blocks and their words are a link to it.

A row is one button that picks its file (any file, whatever its read state); the row takes the highlighter and, while picking, its tick box is ticked. "Pick files to study" in the head (drawn when the space has files, and neither picking nor anything picked) starts picking: every row shows a tick box and the bar rises with "No files picked yet", Cancel and a Study key that waits for a pick. What has its own click sits beside the button: a state with Retry or the lesson link, More and the install line. The kind word's and a linked file's hover tips open on the pointer inside the button, which carries their words as its description for the keyboard and screen readers. The picked bar rises at the bottom while picking or with one or more picked (`PickedBar`, the same bar as the Graph's fact list; it sticks to the foot of the page's scroller in room of its own, so scrolling to the end always shows the last row): the picked files' names in click order, Clear, and Study, which starts a lesson on the files with the first picked first (Lessons on files, `07-study-sessions.md`). A refusal shows the server's reason on the bar. At 8 picked (`MAX_LESSON_FILES`) the other rows no longer pick. Picks end with Clear (Cancel while none is picked), on leaving the page, and for a file that leaves the space.

Linked folders:

- A linked folder adds every supported file, up to `MAX_LINKED_FILES` (500).
- A new linked file takes its name series' kind, else `study`, and is sorted on its first read like any other.
- A recording whose lecture transcript is already in space (same date or lecture number in names, `core::spaces::lecture_transcript`) is never read and records it as `transcriptId`. If that transcript goes, recording is transcribed after all.
- A .tex and the one PDF with the same name in the same folder (any copied PDF of that name, for a copied .tex) are one item (`tex_output_for`, `core::spaces::tex_source`). Pairs are one to one: two PDFs or two .tex files with one name and place pair nothing. Every save of the file list stores the PDF's id on the .tex as `pdfId`. The PDF is read into facts; the .tex has none of its own, and is read after all if the PDF goes. The Files page draws the pair as the PDF's row with ".tex" after its name (both are in one entry of `file_groups`, so the godspeed folder keeps them together), and Remove on it removes both; a picked .tex that joins its PDF's row leaves the picks. `read_space` with `files: true` lists the .tex with its `pdfId`.
- The scan skips the learner's notes folders and any note godspeed wrote there, whose facts are already in the graph (`vault_skip`, [08.1.6](08.1.6-vault-notes.md)).
- A folder that times out (for example Google Drive paused or offline) shows "not responding" and keeps its files, like a missing folder.
- Unreadable files, Google Docs links among them, are counted in folder status and named on Files page.

Reading a study file is a background job on the learner's agent ([5.4](05.4-background-jobs.md)).

### Kept pages

The PDF reader (`agent::subagents::pdf_reader`, a job run by the learner's own agent) reads a page with formulas by rendering it as a picture. When the PDF is a ready space file whose content still matches its `contentFp`, the reader also gets `save_page {page, markdown}` (`services::spaces::kept_pages`, via the job host's `kept_pages` and `keep_page`).

On such a file the brief's page cites (`(p. N)`) come back as the file's source marks (`core::messages::citations::page_marks`), so the teacher copies marks the page draws as links. A PDF that is not a space file, such as one sent in a chat, keeps plain `(p. N)`.

`save_page` writes a whole page as Markdown with LaTeX. It takes only a page whose picture was shown earlier in this job, not one rendered in the same reply.

| Limit | Value |
|---|---|
| Pages per job | 3 |
| Characters per page | 6,000 |
| Too short | under 40% of page's own text, when that text is over 400 characters |

It also refuses empty text, control characters (what JSON makes of an unescaped `\frac` or `\theta`), a newline that broke a `\neq`, `\nu` or similar command, and lines like `--- Page 3 ---`.

- Text is stored, never run, as `texts/<file id>.<fp>.p<N>.md` beside file's saved text (`services::spaces::text_cache`). A new version's text removes old version's kept pages.
- Kept text then stands in for that page (`core::spaces::kept_pages`): in `pdf_extract`, marked `kept` in `pdf_info`, and in search.
- Until then, a lesson's `read_passage` or `search_space_files` result showing a PDF page whose formulas may read broken ends with a line naming page and file's path, so teacher has it looked at with `pdf` first (`services::spaces::space_search`). The signal is `gs_pdf::may_hold_broken_formulas`: a glyph PDF could not map (black square, U+FFFD or private-use character), or 3 or more of math characters `math_density` counts. The line never comes when there is no `pdf` tool to send: not in cheat sheet writer's search, not in a lesson whose learner switched PDF reading off.
- Search index records file's fingerprint plus a hash of its kept pages. A save causes one background re-index, one at a time.
- A passage keeps its id while its place and piece number stay same. A new piece takes a number file never used (`idsUsed`), so a passage id teacher holds still names same page.
- A quote on a kept page is checked against Markdown. The page picture shows its box only when pdfium's own text has words too.

### The teacher's work on a space

While study files wait to be read, the space shows it where the learner is:

- a frame around every tab's page (`src/frontend/components/work/`)
- a tag on space's top-bar tab ("15 left")

Home's "Your spaces" tile leaves it to the strip and the tab.

The record keeps the newest round of work as `lastWork` (`core::spaces::space_work`, applied by the spaces store on every file write). A round opens when a study file starts waiting, collects each file that finishes or fails and each deadline added meanwhile, and ends when nothing waits. A notice in the strip's peek (`work/read-notice.tsx`) then says what the round read until the learner closes it (`DELETE /api/spaces/{id}/work`), new work starts, or a day passes. The space list carries `filesLeft` for the top bar, and `filesRead` while a round is open. A space the teacher makes in the teacher panel's chat opens by itself.

Source marks and page pieces are in [6.4](06.4-source-marks-and-page-pieces.md).

### Deadlines

`SpaceDeadline` (`core::contracts::space`): kind (`exam`, `homework`, `quiz` or `project`), name, due day, optional time on the learner's clock, covered study files, done flag.

- Learner edits them on space's Deadlines tab.
- The teacher panel's chat uses `add_space_deadline` (a list at once), `update_space_deadline`, `remove_space_deadline`.
- `GET /api/deadlines` lists every open deadline for Home.
- Under Home's deadlines, "Unfinished" and "Work on next" each show up to three rows across every open space, from the progress Home already reads for each (`home-next-model.ts`): the newest unfinished lessons, and the weakest topics of each space's Work on next list. A block with no rows is not drawn, and the other then takes the row.
- `GET /api/progress` turns a deadline's files into days left, ready percentage and a "Work on next" list.

Problem lists are in [6.5](06.5-problem-lists.md).

### Deadline requests

One background run of the learner's agent on one deadline (`services::spaces::deadline_requests`, `agent::subagents::deadline_request`). It gets a short fixed prompt, the request (`core::spaces::deadline_requests`) and the space tools it needs: `read_space`, `search_space_files`, `read_passage`, `update_space_deadline`, plus `add_space_file` for a study guide or What it's like. It runs as a job of its own ([5.4](05.4-background-jobs.md)); one the learner asked for goes before godspeed's own jobs. Its changes go into the activity log, so Follow opens the deadline page. It is background work: the activity feed lists it as `{id, title, startedAt}` under `requests`, titled "Deadline: {space} {name}"; Activity shows it with no Stop. The strip's peek names it when it is the only background work, else counts it with the jobs.

| Kind | Started by | Does |
|---|---|---|
| `coverage` | "Ask {teacher}" and "Ask {teacher} to check" under What's on it | works out what deadline covers from space's files and links them |
| `guide` | "Ask {teacher} for a study guide" (an interview with nothing to plan from) | writes `Study guide.md` and links it |
| `about` | "Ask {teacher} to rewrite" under What it's like | rewrites `What it's like.md` |

- One request per deadline at a time, none on a space being checked; another start answers 409. Each start and end emits `deadline-request-changed`.
- `GET /api/spaces/<id>/deadlines/<deadline id>/request` answers `{running, failed}`. While one runs, page sits in work frame. A page request that changed nothing keeps agent's last line (`said`) or why its run stopped (`error`) until next one, in memory only; page shows it beside that Ask key.

### Space checks

godspeed checks a space by itself (`services::spaces::space_checks`): 10 seconds after the app starts (`scan_at_start` in `services::spaces::pipeline::scanner`), at each minute's scan after that, and at once when a deadline is added with nothing linked. The first space with a reason gets one background run with every reason at once, titled "Check: {space}". Reasons (`space_reasons`):

1. an open deadline with nothing linked, in a space with a ready study file
2. a ready info file added after `since`, or read again since its last check (another `contentFp`); a file the agent wrote itself (`written`) never counts
3. a ready study file added after `since` and on or before the due day of an open deadline that has files, in neither its `fileIds` nor `leftOutIds`, and not weighed for it
4. the path ([6.3](06.3-paths.md)) has fewer than 40 topics and 3 or fewer of them are not strong, and this list of topics was not asked about (`pathAsked` holds the space id and a hash of the topic ids)

Rules 2 and 3 skip files added within 60 minutes of the space's first file: the setup run handles those.

- The spaces are scanned at most once a minute (in memory), except for a new deadline.
- One check at a time; a space with a page request running is skipped.
- Tools: the three reading ones, `add_space_deadline` and `update_space_deadline`, plus `update_space` when the path is a reason. Writes must name the checked space and only the arguments in `CHECK_WRITES` (no `done`; on `update_space` only `path` and `description`); others are refused.
- Prompt lists the space's reasons and every deadline, done and past ones too. The check never removes a deadline. On a path it adds up to 10 topics toward the goal (40 at most) and refreshes the description, or says the goal is reached; that list of topics is then not asked about again.
- A run that ends well marks its reasons as asked, even when it changed nothing. One that fails keeps what it wrote, marks nothing, and its space waits one hour (in memory).
- Its changes go into the activity log marked `background`: Follow never moves the page for them.
- A run that changed something keeps each changed deadline's copy before its first change and after its last, and the path and description the same way (the last 20 runs, in memory only). It emits `space-checked` with lines like "Added HW 5, due Fri Nov 20 11:59 PM", "Linked Week 7.pdf to Final", "Added 6 path topics" (`core::spaces::check_lines`).
- `POST /api/spaces/<id>/checks/<run>/undo` removes each deadline the run added and puts back each one it changed, but only while it is as the run left it. It keeps an added deadline that now has a mock or cheat sheet. The path and description go back the same way. It answers `{undone, changedSince, inUse}` with the names it left alone; a run is undone once. The activity log lists it as the learner's: "Undid the check of {space}".

The top bar shows a run that changed something as "{teacher} updated {space}" with its change lines, Undo and a close key (`ChangeCard`, `src/frontend/components/space-notice.tsx`). It waits for the learner; closing removes it for good.

What godspeed asked is in `data/deadline-requests.json` (`{version: 2, asked, since, checkedInfo, weighed, pathAsked, overdueAsked, gapAsked}`), read together with what the Talk chat of earlier versions asked (that record is only read). Version 1 had only `asked`. The first check after the upgrade writes `since`, so older files are never checked. `POST /api/deadlines/<space id>/<id>/not-yet` adds an overdue deadline to `overdueAsked`, which `GET /api/deadlines` also returns. The top bar asks "Is <name> done?" about the oldest overdue deadline not in `overdueAsked` (`overdueToAsk`, `src/frontend/components/space-notice.tsx`) on every page but Home, where the late deadline's card asks with its own Mark done.

Gaps, the deadlines that look missing, are in [6.8](06.8-gaps.md).

Deadline reminders and the menu bar countdown are in [6.6](06.6-deadline-reminders-and-the-menu-bar.md).

Cheat sheets are in [6.7](06.7-cheat-sheets.md).
