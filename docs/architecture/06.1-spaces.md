## 6.1 Spaces

Each space has its own graph. `graph_store_for(app, scope)` (`services::graph::graph`) gives `data/graph/` for "No space" and `data/spaces/<id>/graph/` for a space. Extraction picks the graph from the source's space, so lessons and files write into their own space's graph. A lesson reads only its own space's graph, and `merge_findings` writes only the source's own graph.

Space code:

- `services::spaces::pipeline`: file pipeline, linked-folder scan every 60 s
- `services::spaces::lifecycle`: space lifecycle, cascade delete
- `services::spaces::space_card`: space card
- `services::turns::lessons`: lesson creation

### Space files

A file is `study` (turned into facts) or `info` (the teacher can read it with `read_space`, `search_space_files` and `read_passage`, but it never becomes facts).

Supported files:

- plain text and code, read as is; text files with no extension (checked by bytes)
- PDFs (`crates/pdf`)
- Word and PowerPoint (`crates/files`, `office`, on a small zip reader; slides headed like PDF pages)
- EPUB (`epub`, same zip reader; each spine file is a section headed like a PDF page; copy-protected books and books with no text are refused)
- captions and recordings; recordings are transcribed locally with whisper.cpp (`crates/transcribe`)

Linked folders:

- A linked folder adds every supported file, up to `MAX_LINKED_FILES` (500).
- A new linked file takes its name series' kind, else `study`. While reading a study file agent can say it is logistics (`import_notes` with `may_be_space_info`, decided on first stretch); godspeed then switches it to info (`sortedAsInfo`). A kind picked by hand (`kindChosen`, and every file added by hand) is never re-sorted.
- A recording whose lecture transcript is already in space (same date or lecture number in names, `core::spaces::lecture_transcript`) is never read and records it as `transcriptId`. If that transcript goes, recording is transcribed after all.
- A folder that times out (for example Google Drive paused or offline) shows "not responding" and keeps its files, like a missing folder.
- Unreadable files, Google Docs links among them, are counted in folder status and named on Files page.

Reading a study file is a background work item for the outside agent. Nothing is extracted until an agent takes work.

### Kept pages

The PDF reader (`agent::subagents::pdf_reader`, a job run by the learner's own agent) reads a page with formulas by rendering it as a picture. When the PDF is a ready space file whose content still matches its `contentFp`, the reader also gets `save_page {page, markdown}` (`services::spaces::kept_pages`, via the job host's `kept_pages` and `keep_page`).

`save_page` writes a whole page as Markdown with LaTeX. It takes only a page whose picture was shown earlier in this job, not one rendered in the same reply.

| Limit | Value |
|---|---|
| Pages per job | 3 |
| Characters per page | 6,000 |
| Too short | under 40% of page's own text, when that text is over 400 characters |

It also refuses empty text, control characters (what JSON makes of an unescaped `\frac` or `\theta`), a newline that broke a `\neq`, `\nu` or similar command, and lines like `--- Page 3 ---`.

- Text is stored, never run, as `texts/<file id>.<fp>.p<N>.md` beside file's saved text (`services::spaces::text_cache`). A new version's text removes old version's kept pages.
- Kept text then stands in for that page (`core::spaces::kept_pages`): in `pdf_extract`, marked `kept` in `pdf_info`, and in search.
- Until then, a lesson's `read_passage` or `search_space_files` result showing a PDF page whose formulas may read broken ends with a line naming page and file's path, so teacher has it looked at with `pdf` first (`services::spaces::space_search`). The signal is `gs_pdf::may_hold_broken_formulas`: a glyph PDF could not map (black square, U+FFFD or private-use character), or 3 or more of math characters `math_density` counts. The line never comes when there is no `pdf` tool to send: not in cheat sheet writer's search, not in a lesson whose learner switched PDF reading off.
- Search index records file's fingerprint plus a hash of its kept pages. A save causes one background re-index, one at a time.
- A passage keeps its id while its place and piece number stay same. A new piece takes a number file never used (`idsUsed`), so a passage id teacher holds still names same page.
- A quote on a kept page is checked against Markdown. The page picture shows its box only when pdfium's own text has words too.

### The teacher's work on a space

While study files wait to be read, the space shows it where the learner is:

- a frame around every tab's page (`src/frontend/components/work/`)
- a line on space's row under "Your spaces" on Today
- a tag on space's top-bar tab ("15 left")

The record keeps the newest round of work as `lastWork` (`core::spaces::space_work`, applied by the spaces store on every file write). A round opens when a study file starts waiting, collects each file that finishes or fails and each deadline added meanwhile, and ends when nothing waits. The frame then shows what the round made until the learner closes it (`DELETE /api/spaces/{id}/work`), new work starts, or a day passes. The space list carries `filesLeft` and `building` for Today and the top bar, and `filesRead` while a round is open. A space the teacher makes from its terminal in godspeed opens by itself.

### Source marks

The teacher marks what it read with a source mark right after the sentence:

- `[[f_1a2b3c4d5e6f:7]]`: a passage id from `search_space_files` or `read_passage`
- `[[https://example.com/page]]`: a web page

Prompt part: `crates/agent/prompts/shared/13-source-marks.md`.

`respond` checks every mark before the reply is stored (`services::spaces::citations`):

- A mark whose passage exists is stored as `[[<file id>/<range>/<file name>]]`, for example `[[f_1a2b3c4d5e6f/p. 12/Week 6 slides.pdf]]`, which still points right after passages are renumbered.
- A mark whose passage doesn't exist is removed, and `respond` tells agent which.
- Web marks are stored as written.
- Cheat sheet replies are checked same way. A reply with a bad mark goes back to agent; a quote that does not hold is dropped there without a word.

A mark may quote a few words: `[[f_1a2b3c4d5e6f:7 "degree 12"]]` is stored as `[[f_1a2b3c4d5e6f/p. 14/Lecture 6.pdf|degree 12]]`. The quote is kept only when all hold (`core::messages::quote_find`):

- 2 or more words, or one code expression
- max 80 characters, no `[`, `]`, backticks or `$`
- found exactly once in passage, ignoring spacing, line-end word splits, ligatures and curly quotes

Otherwise the quote is dropped, the plain mark stays, and `respond` says why. In `topic_done`'s `opener.lead`, a bad quote refuses the call.

In a Study lesson, `respond` then reads the reply's own words, not its other tool calls, plus a `quiz` question, a `problem` statement and a `topic_done` opener's lead for a curve (`core::study::reply_nudges`, `services::turns::reply_nudges`). A reply is sent back unstored, with the line below, when its words hold:

| Nudge | When | Agent reads |
|---|---|---|
| Curve | a Markdown table of 3 or more data rows and 2 or more columns, every cell a number, not all 0 or 1, and no header cell starting with step, iteration, t, k, n or i (a worked trace); or two lines (or list items) in a row, each a label and a run of 4 or more numbers | "not sent: these rows read as points of one curve. Send `plot` with the rows as `points` and a prediction instead. If the table is not a curve, send the reply again as it is." |
| Question list | 2 or more list items ending with a question mark, outside code | "not sent: a reply holds one question. Ask the first one now, through `quiz` or `problem` when it checks understanding. If these are not questions for the learner, send the reply again as it is." |

A reply that sends a `plot` gets no curve nudge. Each nudge is sent once a topic (the topic the reply's calls name, else the record's, for a question or statement too; for an opener, the topic it opens), so the same reply sent again is stored. Which were sent is kept in memory only: after a restart a topic may get each again.

The window turns stored marks into numbered buttons and a Sources list (`src/frontend/components/citations/`). A file source opens a popup with the PDF page or passage text; a web source opens the page. The popup reads two routes:

| Route | Returns |
|---|---|
| `GET /api/cited/<file id>?range=<range>&quote=<words>` | `{name, range, page, text, marks}`. `page` is PDF page number when file is a PDF on disk and range names a page, else `null`. `passage=<n>` in place of `range` names passage id `<file id>:<n>` an agent prints. 404 when no space has file, or no passage is at that range or id |
| `GET /api/cited/<file id>/page/<n>` | page as `image/png` |

`marks` places the quote, or is `null` without a quote or when it is not found exactly once:

- PDF page: `{kind: "page", boxes: [{x, y, w, h}]}`, one box per line, as fractions of page image from its top left, cached beside page images
- text or code file: `{kind: "lines", first, lines, spans: [{line, start, end}]}`, the 12 lines centred on quote's first line, positions in UTF-16 units
- anything else (.docx, .pptx, transcripts): `{kind: "passage", start, end}`, UTF-16 offsets in `text`

File ids are unique across spaces, so the routes need no space id. Plain-text readers (Markdown export, extraction) get the mark in words, like ` (Week 6 slides.pdf, p. 12)` (`cites_in_words`). The pure parts are in `core::messages::citations`, with a twin in `src/shared/core/citations.ts`; both replay `crates/core/tests/golden/citations_quotes.json`. Marks inside code and math are left alone.

A Study reply's topic is the one its calls name, else the one before it, else the plan's first topic. A topic's page excerpt comes from the first quoted mark in the shown opener's lead, else in the topic's first reply that is not only reads (`core::study::topic_parts`, twin of `src/shared/core/topic-parts.ts`; both replay `crates/core/tests/golden/topic_parts.json`).

### Deadlines

`SpaceDeadline` (`core::contracts::space`): kind (`exam`, `homework`, `quiz` or `project`), name, due day, optional time on the learner's clock, covered study files, done flag.

- Learner edits them on space's Deadlines tab.
- Outside agents use `add_space_deadline` (a list at once), `update_space_deadline`, `remove_space_deadline`.
- `GET /api/deadlines` lists every open deadline for Today.
- `GET /api/progress` turns a deadline's files into days left, ready percentage and a "Work on next" list.
- Teacher sees them in the `today-context` marker (§5).

### Deadline requests

One background run of the learner's agent on one deadline (`services::spaces::deadline_requests`, `agent::subagents::deadline_request`). It gets a short fixed prompt, the request (`core::spaces::deadline_requests`) and the space tools it needs: `read_space`, `search_space_files`, `read_passage`, `update_space_deadline`, plus `add_space_file` for a study guide or What it's like. The helper takes it when one is open. Its changes go into the activity log, so Follow opens the deadline page. It is background work: the activity feed lists it as `{id, title, startedAt}` under `requests`, titled "Deadline: {space} {name}"; Activity shows it with no Stop. The pill names it when it is the only background work, else counts it with the jobs.

| Kind | Started by | Does |
|---|---|---|
| `coverage` | "Ask {teacher}" and "Ask {teacher} to check" under What's on it | works out what deadline covers from space's files and links them |
| `guide` | "Ask {teacher} for a study guide" (an interview with nothing to plan from) | writes `Study guide.md` and links it |
| `about` | "Ask {teacher} to rewrite" under What it's like | rewrites `What it's like.md` |

- One request per deadline at a time, none on a space being checked; another start answers 409. Each start and end emits `deadline-request-changed`.
- `GET /api/spaces/<id>/deadlines/<deadline id>/request` answers `{running, failed}`. While one runs, page sits in work frame. A page request that changed nothing keeps agent's last line (`said`) or why its run stopped (`error`) until next one, in memory only; page shows it beside that Ask key.

### Space checks

godspeed checks a space by itself (`services::spaces::space_checks`) when an agent starts waiting, or a deadline is added while one teaches. The first space with a reason gets one background run with every reason at once, titled "Check: {space}". Reasons (`space_reasons`):

1. an open deadline with nothing linked, in a space with a ready study file
2. a ready info file added after `since`, or read again since its last check (another `contentFp`)
3. a ready study file added after `since` and on or before the due day of an open deadline that has files, in neither its `fileIds` nor `leftOutIds`, and not weighed for it

Rules 2 and 3 skip files added within 60 minutes of the space's first file: the setup run handles those.

- One check at a time; a space with a page request running is skipped.
- Tools: the three reading ones, `add_space_deadline` and `update_space_deadline`. Writes must name the checked space and only the arguments in `CHECK_WRITES` (no `done`); others are refused.
- Prompt lists the space's reasons and every deadline, done and past ones too. The check never removes a deadline.
- A run that ends well marks its reasons as asked, even when it changed nothing. One that fails keeps what it wrote, marks nothing, and its space waits one hour (in memory).
- Its changes go into the activity log marked `background`: Follow never moves the page for them.
- A run that changed something keeps each changed deadline's copy before its first change and after its last (the last 20 runs, in memory only), and emits `space-checked`.
- `POST /api/spaces/<id>/checks/<run>/undo` removes each deadline the run added and puts back each one it changed, but only while it is as the run left it. It keeps an added deadline that now has a mock or cheat sheet. It answers `{undone, changedSince, inUse}` with the names it left alone; a run is undone once.

What godspeed asked is in `data/deadline-requests.json` (`{version: 2, asked, since, checkedInfo, weighed, pathAsked, overdueAsked}`), read together with what the Talk chat of earlier versions asked (that record is only read). Version 1 had only `asked`. The first check after the upgrade writes `since`, so older files are never checked. `POST /api/deadlines/<space id>/<id>/not-yet` adds an overdue deadline to `overdueAsked`, which `GET /api/deadlines` also returns.

### Deadline reminders

`services::app::deadline_reminder` sends at most one system notification a day, for the soonest open deadline 3 days away or less.

1. Server checks 10 s after start, then every 10 minutes. Each wait reads wall clock, so a computer that slept through 9:00 still sends within 10 minutes of waking.
2. From 9:00 local time on, it picks deadline and writes text, for example "Quiz 2 is in 2 days" with "Algebra. You are 40% ready." (percentage from `progress_for`). A deadline with problems says "Algebra. 2 of 7 problems done." With neither, only space name shows.
3. Server asks shell with `notify`. The shell skips it while main window has focus and answers whether it showed it.
4. Only a shown reminder marks day in `data/reminders.json` (`store::reminders`, `{version: 1, lastDay}`). A skipped one is retried at a later check.

A server without a shell runs no check. Settings, General, Deadline reminders (`general.deadlineReminders`, on by default, desktop app only) turns them off, read at each check.

### Cheat sheets

A deadline's header has a Cheat sheet button opening its studio (`/space/deadline/<id>/cheat-sheet`). The outside agent makes the sheet as a real PDF with its own tools (LaTeX suggested); godspeed shows that file as is.

Record: `spaces/<id>/cheat-sheets/<deadlineId>.json` (`store::cheat_sheets`, format 4, removed with its deadline), holding:

- last 5 versions, each a PDF in `<deadlineId>-versions/v<n>.pdf` with page sizes and message that made it, or marked as taken from working folder
- sheet's chat (last 100 messages) and rules
- working folder's name

Pictures and PDFs sent in the chat sit in `<deadlineId>-files/`, named by content. `core::study::cheat_sheet` reads older formats: format 3's prompts become the chat's first messages; an HTML or block sheet (formats 2 and 1) keeps its asks and offers Make it again.

Each chat message is one background work item (`sheet_reply`, `agent::subagents::cheat_sheet_writer`), not a chat kind, so lessons, search and extraction never see it. The request carries:

- deadline's topics with readiness and a few facts, and mistakes from practice
- sheet's rules and last 8 messages
- working folder `<godspeed folder>/cheat-sheets/<space> <deadline>/`, where agent keeps its source
- message: learner's words and files, and part of a page they pointed at, picture first

The agent answers in markdown. If it changed the sheet, it sends the new PDF's path and any rules the learner set (`new_rules`). Its instructions: render and look at every page, check each formula against the space's material.

godspeed takes a PDF only from inside the working folder, links resolved (`services::cheat_sheets::cheat_sheet_pdf`). It checks the PDF by bytes (at most 20 MB, 1 to 4 pages, each 2 to 17 inches), then copies it into its data. Opening a sheet also takes the newest PDF in the working folder when newer than the current version (an edit outside godspeed), after the same checks, once per file.

The studio is a canvas (`src/frontend/components/cheat-sheet/`):

- Every kept version's pages are artboards, newest first, drawn by pdf.js (served at `/pdfjs/`, outside `/api`, `server::http::ui`).
- Each page is drawn whole once, then visible part again at screen resolution once view settles, so it stays sharp at any zoom.
- Point at sheet draws a box on a page; that part goes with next message as a picture.
- Chat floats on right (`sheet-chat.tsx`): rules with a remove button, messages, "Made version N" rows, Stop and Try again, and a box with math, pictures, PDFs and a kept draft.
- Print draws pages at 300 dpi into print-only pictures. On desktop, Show in Finder reveals PDF in working folder (`window.lh.showInFolder`); a browser gets a download link.

In a space's lesson, the top bar's Cheat sheet button docks a sheet beside the lesson (`sheet-dock.tsx`, resizable, open state kept per lesson). It shows the lesson's deadline's sheet, else the space's next one with a sheet, with a picker when several. The docked sheet has no chat: questions go to the teacher in the lesson box.

A space's Cheat sheets tab (`/space/cheat-sheets`, `GET /api/spaces/<id>/cheat-sheets`) shows every deadline but interviews as a card, coming up first. A card says whether its sheet is made (with page 1 preview), being made, older (Make it again) or missing (Make one).
