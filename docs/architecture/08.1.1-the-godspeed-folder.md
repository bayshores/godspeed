## 8.1 The agent boundary: the godspeed folder

### The godspeed folder

The agent works in one folder, `~/godspeed` by default. `data/agent-folder.json` remembers another one, whether the one-time notice was seen, `startCommands`, `talkExported` (see [Talking to the agent outside lessons](08.1.3-agent-tools-and-notes.md#talking-to-the-agent-outside-lessons)). Debug build uses `<data>/godspeed-folder`.

The agent works in it: every lesson, job and teacher panel chat runs its session there. `services::app::agent_folder` writes `.godspeed/setup-spaces.md` from `crates/services/folder-files/` (`folder_files.rs`) once per app start, so updates reach it: the steps for setting up spaces, which the teacher panel's prompt points at. Writing it also removes what an older godspeed left and no longer uses: in `.godspeed/` its connection, hook and start scripts, its `package.json` and `claude-settings.json`, and `images/`, which it rewrote at every start; the old `/setup-classes` and `/setup-spaces` skills; and `CLAUDE.md`, `AGENTS.md` and `.mcp.json` only while each is still godspeed's (the two instructions files still start with the line saying godspeed rewrites them, `.mcp.json` names godspeed's server and no other). The learner's own files and `.godspeed/attachments/` stay. The folder is set up when that file is there.

The agent's instructions are godspeed's own prompts, never files in the folder: Claude Code runs with no setting sources and Codex reads no project document ([8.1.4](08.1.4-how-the-agent-starts.md)).

**The teacher's chats.** The teacher panel's chats are chat records of kind `talk` ([8.1.8](08.1.8-the-teacher-panels-chat.md)). The chats an older build kept for the teacher's terminal (`data/teacher-chats.json`) are carried over once and the file is kept aside.

The teacher's panel, window side (`src/frontend/components/teacher/`):

| Piece | What it does |
|---|---|
| Panel | The teacher panel's body is godspeed's own chat with the teacher, where the learner talks to it outside lessons ([8.1.8](08.1.8-the-teacher-panels-chat.md)). It stays open while the learner works on the page, a lesson too. The strip opens and closes it; the head has no Hide key. **Head** (`panel-head.tsx`, the top bar's look): the teacher's name with a square breathing while it works, Chats, Follow (held down while the window goes where the teacher works), Activity and Pop out. **Activity** drops its list over the chat's top (the chat dims under it), hanging from the head, with the keyboard in it; a log to read: rows are plain text, no clicks; a click outside or on Activity closes it; Esc returns the keyboard to Activity. **Strip** while the panel is open: the arrow, now pointing back at the edge, and marks only, the teacher's name and state left to the panel's head; a click closes the panel. The page is never dimmed and takes clicks beside the panel. **Look**: a sheet in the top bar's color sliding out of the strip and back into it (`.lh-dock`); the chat under its head has the page's colors (`.lh-page-colors`). **What the teacher can be asked**: "Try asking" in a new chat, Ideas in its writing row, and a page key that hands the teacher one line (`ask` on the teacher context, `teacher-provider.tsx`), which the chat sends as if typed; `canAsk` is false while the chat is popped out. Files shows "Ask <teacher> to look inside" beside "No file names have …" when a name search finds nothing |
| Size | A square column from top bar down to window's bottom, left of the strip (620 px wide at first), pushing page left by its width. Learner drags left edge (`ResizeHandle`, 360 to 900 px, kept as `lh:pane-width:teacher`); double-click restores default; edge takes arrow keys. Narrower than asked where page would drop under 480 px, covering a page with no room for even 360 px (`panelLayout`, `dock-model.ts`). A page with its own bar (a mock) is pushed same way; its bar stays whole across window, over panel (`.lh-own-bar`, `globals.css`). Under 640 px panel takes whole window, nothing to drag |
| Opening | A click on the strip opens the panel on its chat, whose box takes the keyboard. It opens by itself when a card in its chat waits to be allowed, once they have paused typing, and closes when that is settled or a lesson reply starts (`panel-auto-model.ts`); opened that way it leaves the keyboard where it is. It also opens once for a new learner: onboarding's finish leaves a mark in browser storage (`WELCOME_KEY`), and the first look at Home once the chats are read opens the panel and removes the mark (`welcomeNow`), so the "Try asking" row is in front of them |
| Onboarding | Step 1 is the setup card ([the agent's setup](08.1-the-outside-agent-boundary.md#the-agents-setup)) |
| Say it once | The panel's head names the teacher. Its chat's own work shows in the thread; while the teacher works elsewhere (a lesson's turn, a job, Follow's round) the name gives way to "Working" |
| Starts | Lessons, jobs and the panel's chat run in sessions of their own, on the agent picked on the setup card (`agent` on `GET /api/agent-folder`, null until a pick), or on Claude Code before a pick. The folder notice's "Set up my folder" (an older setup moving to the godspeed folder) makes the folder, picks the old setup's agent and removes the old setup |
| Restart now | Asks first while a lesson turn runs |
| Pop out | "Pop out" in the panel's head moves the chat to the shell's second window (`routes/chat-window.tsx`, `teacher/chat-window.tsx`; [tauri-shell/the-main-window.md](../tauri-shell/the-main-window.md#the-chat-window)). One owner holds "popped": `useChatWindow` (`use-chat-window.ts`), called once by the teacher provider and set by `window.lh.chatWindow.onChange` |
| While popped out | The teacher's panel (`view` `popped`) has Activity as its body and in its head Follow and "Put back". Put back, in either window, closes the window and opens the panel on the chat the window showed: the shell's push says `back`, `useChatWindow`'s `putBacks` counts it and `useTeacherPanel` opens the panel at each. The window's own close button closes it and leaves the panel as it is. The panel never opens by itself meanwhile: the strip lights, and a click on it brings the window forward |

### The spaces folder

The godspeed folder also gets `spaces/`, with a shortcut to every space file grouped like the Files page (`spaces/<space>/<group>/<file>`, closed spaces under `spaces/Closed/`) and a `READ ME.txt`.

- `core::spaces::space_shortcuts` picks names (safe on every OS, " (2)" for a repeat) from `core::spaces::file_groups`.
- `services::spaces::space_shortcuts` writes them when folder is set up and about 2 s after `spaces-changed`.
- Shortcuts are symlinks, or hard links on Windows when symlinks aren't allowed. `.godspeed/shortcuts.json` lists what sync made; it removes only those, then each folder it made that is left empty. So older builds' `spaces/Archived/` goes once its shortcuts move to `spaces/Closed/`, and stays only while it holds something of learner's.
- Copies in data folder are read-only on macOS and Linux. Moving godspeed folder clears old `spaces/`.
- Linking or adding a path inside `spaces/` is refused (`shortcut_path_problem`).
- `made/<space name>/` is where the agent builds files for the learner (a practice test and its `.tex`), as its prompt says. godspeed never writes or clears it. A file added from there is the agent's own ([agent tools](08.1.3-agent-tools-and-notes.md)); a `.tex` beside its PDF shows as one file.
