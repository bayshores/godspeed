## 8.1 The outside-agent boundary: the godspeed folder

### The godspeed folder

Agents open in one folder, `~/godspeed` by default. `data/agent-folder.json` remembers another one, whether the one-time notice was seen, `startCommands`, `talkExported` (see [Talking to the agent outside lessons](08.1.3-agent-tools-and-notes.md#talking-to-the-agent-outside-lessons)). Debug build uses `<data>/godspeed-folder`.

`services::app::agent_folder` writes it from `crates/services/folder-files/` and `core::spaces::agent_folder`, once per app start so updates reach it:

- `CLAUDE.md` (for Claude Code) and `AGENTS.md` (for Codex): what the agent in godspeed's terminal does when the learner names a topic or types to it. Each says godspeed rewrites it; learner notes belong in `CLAUDE.local.md` or `~/.codex/AGENTS.md`. Both say the learner's notes folder is read only with `search_vault` and written only with `write_vault_note` ([08.1.6](08.1.6-vault-notes.md)). Both say how to update a space when the learner asks: its new info files, where its deadlines are posted (asked once, kept with `remember`), then what else is due ([6.8](06.8-gaps.md)).
- `.godspeed/setup-spaces.md`: the steps for setting up spaces, which both instructions point at. A plain file, since Claude Code starts with skills off.
- `.mcp.json`, running `.godspeed/connect.mjs`, a stdio bridge to `/api/mcp`
- in `.godspeed/`: scripts, `claude-settings.json`, a start script per agent

`claude-settings.json` loads with `--settings`, so it applies before the folder is trusted. It turns on the folder's server, allows godspeed's tools and web search, adds the prompt hook (`typed.mjs`, see [Talking to the agent outside lessons](08.1.3-agent-tools-and-notes.md#talking-to-the-agent-outside-lessons)) and `agent-event.mjs` on SessionStart, Stop, Notification (a permission or a question) and, in the background (`async`), PreToolUse for the agent's own tools. Codex gets the same hooks through `-c` (PermissionRequest for Notification; PreToolUse only for its commands and patches). `agent-event.mjs` posts to `/api/mcp/agent-event`, only from godspeed's terminals: which chat the terminal runs (for the chat list), a stop and a need (for the sound), and each own tool with a subject it cuts first (for Follow's slip, [8.1.7](08.1.7-follows-slip.md#the-agents-own-tools)). The window plays its soft `done` sound (`teacher/use-done-sound.ts`, behind the Sounds switch) while the learner looks away: a lesson's or cheat sheet's reply while godspeed isn't the front window, and the teacher answering a line typed to it in its terminal, or needing the learner, while that terminal is closed too. Fetching a page still asks, since text hidden in a space file could send the learner's data out. Codex gets the same connector via `-c` flags with tools pre-approved, no project config.

Starting an agent:

1. "Start Claude Code" (`src/frontend/components/agent-folder/`) writes folder.
2. Shell (`window.lh.terminals.start`, `crates/shell/src/terminal/`) runs start script in its own terminal, shown in window ([tauri-shell/terminals.md](../tauri-shell/terminals.md#terminals)). Only those scripts can run.
3. Start script stops with an install hint when agent's command or Node.js is missing (`start_script`, `core::spaces::agent_folder`), since connector and hooks run with plain `node`. Exit 3 = missing agent, 4 = missing Node.js, 6 = Claude Code too old, so window can say which.
4. The teacher's script has two starts. `GODSPEED_RESUME` set (the window picked an earlier chat): `claude --resume <id>`, `codex resume <id>`. Otherwise a new chat with no first prompt, in godspeed's terminal and outside it (the copied command, which on Windows runs the script for Codex).

**The teacher's chats.** The teacher panel's chats are chat records of kind `talk` ([8.1.8](08.1.8-the-teacher-panels-chat.md)). The chats an older build kept for the teacher's terminal (`data/teacher-chats.json`) are carried over once and the file is kept aside.

Window side (`src/frontend/components/terminal/`):

| Piece | What it does |
|---|---|
| `use-terminals.ts` | the teacher's latest terminal; starting and stopping it. Lessons and jobs never start it ([background jobs](05.4-background-jobs.md)) |
| Panel | The teacher panel's body is godspeed's own chat with the teacher, where the learner talks to it outside lessons ([8.1.8](08.1.8-the-teacher-panels-chat.md)). It stays open while the learner works on the page, a lesson too. The strip opens and closes it; the head has no Hide key. **Head** (`panel-head.tsx`, the top bar's look): the teacher's name with a square breathing while it works, Chats, Follow (held down while the window goes where the teacher works), Activity and Pop out. **Activity** drops its list over the chat's top (the chat dims under it), hanging from the head, with the keyboard in it; a log to read: rows are plain text, no clicks; a click outside or on Activity closes it; Esc returns the keyboard to Activity. **Strip** while the panel is open: the arrow, now pointing back at the edge, and marks only, the teacher's name and state left to the panel's head; a click closes the panel. Files shows "Ask <teacher> to look inside" beside "No file names have …" when a name search finds nothing |
| Size | A square column from top bar down to window's bottom, left of the strip (620 px wide at first), pushing page left by its width. Learner drags left edge (`ResizeHandle`, 360 to 900 px, kept as `lh:pane-width:teacher`); double-click restores default; edge takes arrow keys. Narrower than asked where page would drop under 480 px, covering a page with no room for even 360 px (`panelLayout`, `dock-model.ts`). A page with its own bar (a mock) is pushed same way; its bar stays whole across window, over panel (`.lh-own-bar`, `globals.css`). Under 640 px panel takes whole window, nothing to drag. **Font and grid**: one font size (13 px, as head and footer) at every size; columns and rows = what fits box (`gridSize`, `terminal-model.ts`; cell measured from xterm's drawn screen; min 40 by 10). Shell gives agent's terminal same size (`terminals.resize`) before screen attaches and 80 ms after a drag rests. Ended screen keeps final size, scrolls inside its box |
| Opening | Click on the strip, teacher's status line (Settings tile), or the folder notice's start opens the panel on its chat, whose box takes the keyboard. It opens by itself when a card in its chat waits to be allowed, once they have paused typing, and closes when that is settled or a lesson reply starts (`teacher/panel-auto-model.ts`); opened that way it leaves the keyboard where it is. It also opens once for a new learner: onboarding's finish leaves a mark in browser storage (`WELCOME_KEY`), and the first look at Home with the teacher on opens the panel and removes the mark (`welcomeNow`), so the "Try asking" row is in front of them. Then the strip lights with "needs you", status lines say what is needed, a click on the strip opens the screen. Once a terminal checked in, a long quiet never counts as starting again. System holds back a background window's timers, so window returning or taking focus looks again |

| Say it once | The panel's head names the teacher. Its chat's own work shows in the thread; while the teacher works elsewhere (a lesson's turn, a job, Follow's round) the name gives way to "Working" |
| Starts | Only the learner starts the teacher's terminal, from the folder notice's "Set up my folder" (an older setup moving to the godspeed folder). Lessons, jobs and the panel's chat run without it, on the agent picked on the setup card (`agent` on `GET /api/agent-folder`, null until a pick), or on Claude Code before a pick. Start while an agent outside godspeed is connected still sets up folder and says why it starts nothing |
| Restart now | Asks first while a lesson turn runs (`turnsRunning` on `GET /api/mcp-access`) |
| Pop out | "Pop out" in the panel's head moves the chat to the shell's second window (`routes/terminal-window.tsx`, `teacher/chat-window.tsx`; [tauri-shell/the-main-window.md](../tauri-shell/the-main-window.md#the-terminal-window)). ### The spaces folder

The godspeed folder also gets `spaces/`, with a shortcut to every space file grouped like the Files page (`spaces/<space>/<group>/<file>`, closed spaces under `spaces/Closed/`) and a `READ ME.txt`.

- `core::spaces::space_shortcuts` picks names (safe on every OS, " (2)" for a repeat) from `core::spaces::file_groups`.
- `services::spaces::space_shortcuts` writes them when folder is set up and about 2 s after `spaces-changed`.
- Shortcuts are symlinks, or hard links on Windows when symlinks aren't allowed. `.godspeed/shortcuts.json` lists what sync made; it removes only those, then each folder it made that is left empty. So older builds' `spaces/Archived/` goes once its shortcuts move to `spaces/Closed/`, and stays only while it holds something of learner's.
- Copies in data folder are read-only on macOS and Linux. Moving godspeed folder clears old `spaces/`.
- Linking or adding a path inside `spaces/` is refused (`shortcut_path_problem`).
- `made/<space name>/` is where the agent builds files for the learner (a practice test and its `.tex`), as `CLAUDE.md` and `AGENTS.md` say. godspeed never writes or clears it. A file added from there is the agent's own ([agent tools](08.1.3-agent-tools-and-notes.md)); a `.tex` beside its PDF shows as one file.
