## 8.1 The outside-agent boundary: the godspeed folder

### The godspeed folder

Agents open in one folder, `~/godspeed` by default. `data/agent-folder.json` remembers another one, whether the one-time notice was seen, `startCommands`, `talkExported` (see [Talking to the agent outside lessons](08.1.3-agent-tools-and-notes.md#talking-to-the-agent-outside-lessons)). Debug build uses `<data>/godspeed-folder`.

`services::app::agent_folder` writes it from `crates/services/folder-files/` and `core::spaces::agent_folder`, once per app start so updates reach it:

- `CLAUDE.md` (Claude Code's work loop with waiter) and `AGENTS.md` (Codex's). Each says godspeed rewrites it; learner notes belong in `CLAUDE.local.md` or `~/.codex/AGENTS.md`.
- `setup-spaces` skill
- `.mcp.json`, running `.godspeed/connect.mjs`, a stdio bridge to `/api/mcp`
- in `.godspeed/`: scripts, `claude-settings.json`, a start script per agent and role

`claude-settings.json` loads with `--settings`, so it applies before the folder is trusted. It turns on the folder's server, allows godspeed's tools, the waiter and web search, adds the forget and compacting hooks, the prompt hook (`typed.mjs`, see [Talking to the agent outside lessons](08.1.3-agent-tools-and-notes.md#talking-to-the-agent-outside-lessons)) and `agent-event.mjs` on SessionStart, Stop and Notification (a permission or a question). Codex gets the same hooks through `-c` (PermissionRequest for Notification). `agent-event.mjs` posts to `/api/mcp/agent-event`: which chat the terminal runs (for the chat list), a stop and a need (for the sound and the nudge). The window plays its soft `done` sound (`teacher/use-done-sound.ts`, behind the Sounds switch) while the learner looks away: a lesson's or cheat sheet's reply while godspeed isn't the front window, and the teacher answering a line typed to it in its terminal, or needing the learner, while that terminal is closed too. Fetching a page still asks, since text hidden in a space file could send the learner's data out. Codex gets the same connector via `-c` flags with tools pre-approved, no project config.

Starting an agent:

1. "Start Claude Code" (`src/frontend/components/agent-folder/`) writes folder.
2. Shell (`window.lh.terminals.start`, `crates/shell/src/terminal/`) runs start script in its own terminal, shown in window ([tauri-shell/terminals.md](../tauri-shell/terminals.md#terminals)). Only those scripts can run.
3. Start script stops with an install hint when agent's command or Node.js is missing (`start_script`, `core::spaces::agent_folder`), since connector and hooks run with plain `node`. Exit 3 = missing agent, 4 = missing Node.js, so window can say which.
4. The teacher's script has three starts. `GODSPEED_RESUME` set (the window picked an earlier chat): `claude --resume <id>`, `codex resume <id>`. In godspeed's terminal (`GODSPEED_TERMINAL` set): a new chat with no first prompt; godspeed nudges it when work waits ([the work loop](08.1.2-the-work-loop.md#the-work-loop)). Anywhere else (the copied command on Windows runs the script): "Start teaching". The helper's script always starts a new chat with "Start as the helper".

**The teacher's chats.** `data/teacher-chats.json` (`core::records::teacher_chats`, `services::app::teacher_chats`) keeps the newest 20: the SessionStart hook names the chat a teacher terminal runs (also one `/resume` opened inside the agent; the server then uses that id as the agent's, since the connector keeps the one it started with). A chat is listed once used: a line typed to it names it, a lesson it answers names it after the lesson. `GET /api/teacher-chats` gives the newest 5 from the current folder (agents keep chats per folder), each with `open`: the teacher's terminal runs it now. Before the teacher's first start the panel's screen lists them under New chat; once the teacher has a screen, the head's Chats key does. Agent-seen marks stay keyed by the same id, so a resumed chat gets only what it has not seen.

In a browser there is no `window.lh.terminals`: Start makes the folder and the learner copies the command into their own terminal.

A learner starting an agent through a launcher sets its command with Change command under the Start button: one line, at most 300 characters (`usable_start_command`). Empty goes back to `claude` or `codex`.

`services::app::old_setup` finds and removes leftovers of the retired Claude Code plugin and old Codex config block. A notice under the pill and a line in Settings, Connection offer Remove.

### The spaces folder

The godspeed folder also gets `spaces/`, with a shortcut to every space file grouped like the Files page (`spaces/<space>/<group>/<file>`, closed spaces under `spaces/Closed/`) and a `READ ME.txt`.

- `core::spaces::space_shortcuts` picks names (safe on every OS, " (2)" for a repeat) from `core::spaces::file_groups`.
- `services::spaces::space_shortcuts` writes them when folder is set up and about 2 s after `spaces-changed`.
- Shortcuts are symlinks, or hard links on Windows when symlinks aren't allowed. `.godspeed/shortcuts.json` lists what sync made; it removes only those, then each folder it made that is left empty. So older builds' `spaces/Archived/` goes once its shortcuts move to `spaces/Closed/`, and stays only while it holds something of learner's.
- Copies in data folder are read-only on macOS and Linux. Moving godspeed folder clears old `spaces/`.
- Linking or adding a path inside `spaces/` is refused (`shortcut_path_problem`).
