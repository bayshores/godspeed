## 8.2 Plugins

A plugin is a folder with a `manifest.json` (`services::plugins::manifest`), its page and files. The window shows the page in an iframe sandboxed without `allow-same-origin`: opaque origin, reaching godspeed only by messages to the window.

| Part | How |
|---|---|
| Install | `POST /api/plugins`: `{ from: "folder", folder }` copies a local folder; `{ from: "list", id }` downloads list entry `id`'s tag (`codeload.github.com/<owner>/<repo>/zip/refs/tags/<tag>`), taking only its `path` folder when entry names one (godspeed's own plugins are folders of list repository). Only way a GitHub plugin comes in, so window can't name another repository. Files go to a staging folder, manifest checked there, then it takes plugin's place and keeps its `data/`. Refused: links, `..`, roots, drives, backslashes. Hidden files left out. Max 1000 files, 20 MB |
| List | `GET /api/plugin-list` (`services::plugins::list`): `plugins.json` of github.com/bayshores/godspeed-plugins, read by server from `raw.githubusercontent.com/bayshores/godspeed-plugins/HEAD/plugins.json` only (`gs_web::plugin_list`): no redirect followed, User-Agent `godspeed`, nothing of learner's sent, 10 s, 256 KB. Read again each time Plugins tab asks; on failure last list read in this run answers (empty before first), and an install looks its entry up there, never fetching list itself. Non-JSON text, unknown `version` or list over cap reads as empty; bad entry (including a `path` that isn't one folder name of `a-z`, `0-9`, `-`) left out; of two with one id, first kept. Debug server reads file `LH_PLUGIN_LIST` names instead |
| Reviewed access | A list install refuses tag, keeping nothing, when its manifest's `id`, `uses`, `network`, `lesson` or `space` differ from entry's. It writes `{ repo, tag, path? }` to `.source.json` in plugin's folder: hidden, so a plugin's own files can't bring one and no route serves it; a folder install drops it. The plugin's view carries it as `source`; Settings shows Update when list names another repo, tag or path. An update is same install, so on/off, values and `data/` stay |
| State | `settings.json` `plugins.<id>`: `enabled` (absent is on), `values` checked against manifest's settings. A stale value reads as default |
| Files | `GET /plugin-files/<id>/<path>`, outside /api, only while plugin on, never from `data/`. Served only at `localhost:<port>`, never at window's `127.0.0.1`: no Tauri capability names `localhost`, so a post from frame to window's IPC handler is refused by capability check even with invoke key. Window lets a frame load there (`shell::window`, `is_plugin_page`). Every answer carries a CSP from manifest (`services::plugins::csp`): code only from plugin's own folder, fonts also from `/plugin-fonts/`, network only at its `network` hosts, framed only by window, `sandbox allow-scripts` even opened on its own. `Access-Control-Allow-Origin: *` lets module scripts and fonts load from opaque origin |
| Fonts | `GET /plugin-fonts/<name>.woff2`: a built font from `ui/assets/`, only at `localhost:<port>`, only `.woff2` names, never to a request with a cookie, with `Access-Control-Allow-Origin: *`. At initialize page gets the app's `@font-face` rules for `--font-sans` as `hostContext.styles.css.fonts`, each built file pointed there (`hostFonts`), each inlined one as is |
| /api | frame's requests are `Sec-Fetch-Site: cross-site` and carry no window cookie (it belongs to `127.0.0.1`), so access gate refuses them, and CSP blocks them first |
| Frame | `PluginFrame` speaks MCP Apps (protocol 2026-01-26) to page, checks each host tool against manifest. Look maps standard variables to what frame sits on, read at frame (`styleTokens`): on a space's tab, sheet (background primary `--lh-sheet`, secondary `--background`, a well on a sheet); in a lesson's window (made of top bar like every pop-up), bar (primary `--background`, secondary `--card`, theme dark). Tertiary is `--accent` (tone) on both. A second frame load is a navigation: bridge stops, frame shows it didn't load |
| Lesson window | `PluginWindow`: plugin's word on the top bar (among the open lesson's words, `lesson-bar.tsx`) opens a window hanging from the bar over the page, in the Teacher's window shell (`BarWindow`), right edge on the word's; follows it when the window resizes. 360 px wide; height = page's `ui/notifications/size-changed` height (120 px until first), from 48 px to room under bar less 16 px (`plugin-window-model.ts`). Word, Escape, cheat sheet and Teacher's window close it; it and Teacher's window never show together |
| `get_context` | `{ space, topic, question, lastAnswered, teacherMessage }`. In a lesson (`lesson-plugins-model.ts`): `topic` = lesson's title; `question` = open question on screen (`{ id, text, options }`, its tool call id; left out while it waits behind "Check your understanding", never with its answer); `lastAnswered` = last question answered or skipped, with `answer` (quiz's marked options, explain question's committed answer) and `correct` (graded quiz only, never prediction, "I don't know" or skip), as its answered card shows them. On a space's tab only `space` is set |
| Changes | Once initialized, a change to what `get_context` gives comes as `ui/notifications/host-context-changed` with `{}`, 0.5 s after things hold still, compared by value. The page calls `get_context` again. Setting values come only at initialize, as `hostContext.settings` |
| Storage | `GET` and `PUT /api/plugins/<id>/storage/<key>`: one JSON file per key in `data/`, key of letters, digits, `_`, `-`, max 1 MB |
| `ask_agent` | `POST /api/plugins/<id>/ask`: one submit job for learner's agent (`agent::subagents::plugin_asker`), labelled "<name> asked for…". Only with `uses: ["agent"]`, while on, one at a time per plugin, prompt and schema max 4 KB each. Answer wrapped as one field (a tool's parameters must be an object). A running request is a `requests` row of activity feed (`{ id: "plugin:<id>", title: <name> }`, beside deadline requests), so pill (when only work) and Activity list name it, and agent's status line says "Working" as for a deadline request; no work frame (not work on page) |
