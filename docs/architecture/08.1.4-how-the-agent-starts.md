# 8.1 The agent boundary: how the agent starts

What every session of the learner's agent is started with, and what that leaves out. The teacher needs godspeed's tools and nothing else; everything else loaded at start is standing context that every request pays for (the learner's own plugins, MCP servers, skills and subagents can add tens of thousands of tokens).

## Claude Code

godspeed's Claude helper (`crates/runtime/src/claude/claude-helper.mjs`) starts each session through the Agent SDK, on the learner's own `claude`, in the godspeed folder.

| Option | What it leaves out or sets |
|---|---|
| `settingSources: []` | The learner's own settings, hooks, skills, `CLAUDE.md` files and MCP servers |
| `strictMcpConfig: true`, `mcpServers` | Only godspeed's tool server, in the helper's own process |
| `disallowedTools: ["Agent", "Skill"]` | The subagent tool and skills |
| `systemPrompt` | Claude Code's own prompt with godspeed's instructions for the session appended |
| `canUseTool` | godspeed's tools and web search run without asking; any other tool waits for the learner on a card ([5.3](05.3-the-agent-session.md)) |
| `PostToolUse` hook | A question for the learner ends the turn right after its result |

## Codex

godspeed runs `codex app-server` with its own Codex folder and gives each thread godspeed's tools as dynamic tools. Each thread's config (`thread_config`, `crates/runtime/src/codex/wire.rs`) turns off the ChatGPT apps of the account signed in, subagents and the list of skills, and reads no `AGENTS.md` (`project_doc_max_bytes: 0`). `app-server` starts with `--disable memories`, `memories.generate_memories=false` and `memories.use_memories=false` (`APP_SERVER`, `crates/runtime/src/session.rs`), so Codex neither writes nor reads memories of its own: godspeed's `remember` and `forget` notes are the only memory. Codex's state database still makes `memories_1.sqlite` in its folder when it starts.

## The learner's own start command

A learner who starts an agent through a launcher sets its command with Change beside "Start command" in Settings, Teacher: one line, at most 300 characters (`usable_start_command`). Empty goes back to `claude` or `codex`. The setup card asks such a command nothing.

## Old setups

`services::app::old_setup` finds and removes leftovers of the retired Claude Code plugin and old Codex config block. A corner notice on app start offers Remove; Later hides it until the next start.
