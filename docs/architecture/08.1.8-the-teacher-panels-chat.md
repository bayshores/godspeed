### 8.1.8 The teacher panel's chat

The teacher panel's body is godspeed's own chat with the teacher, where the learner talks to it outside lessons. It reads like a narrow lesson page: the learner's lines are plates at the right, the teacher's words lie open in the reading type, its steps and Allow cards sit on the desk, and the newest is at the foot.

#### The server

A chat is a chat record of kind `talk` in the lessons' store (`data/chats/<id>.json`), so its turns run like a lesson's: the same chat lock, stream, Stop (`abort_turn`), desk (`TurnWork`, cause `talk`) and Allow cards, through `SessionTurn`. Only its setup differs (`crates/services/src/talk/`):

| Piece | What it does |
|---|---|
| `setup.rs` | The talk prompt (`prompt.rs`: godspeed's own text, the memory rules and the space steps) and the 24 data tools. A new session's first message opens with "Where you left off" (`talk_opening`), so the prompt stays the same and keeps its cache. |
| `tools.rs`, `tools.json`, `tools/` | The data tools: `checked_arguments` checks a call against its schema and refuses bad arguments in fixed words (`tests/talk_tool_arguments.rs`), then `run_tool` runs it. |
| `mod.rs` | `talk_chats` (the list), `create_talk_chat` (named by its first line, cut to 60 characters, "A chat" for a picture alone, on a model picked before it was made), `set_talk_model`, `earlier_words`. |
| `old_chats.rs` | The teacher's chats from the terminal an older build had (`data/teacher-chats.json`). The first time the list is read, each used Claude Code chat from the current godspeed folder becomes a talk record with `terminalChat` and an `agentSession` whose `promptHash` and `seen` are null, which goes on with that session as it is. The file is then kept aside as `teacher-chats.json.carried-over-<ms>`; a damaged one is kept aside as `.corrupt-<ms>`. Codex kept its chats in the learner's own Codex folder, which godspeed's Codex cannot read, so they are not carried over. |

A talk chat takes a message, a line sent while it works (a steer) and Try again (`continue`); any other input is refused. Steps come from `lesson_steps::talk_call`: godspeed's tools and the agent's own each say what they do; nothing is logged in the chat, since Activity keeps what the teacher changed.

| Route | Does |
|---|---|
| `GET /api/chats?kind=talk` | The chats, newest first: `{id, title, createdAt, updatedAt, kind, model, agent, running}`, `model` being the one its next reply runs on (null: the agent's own default). Lessons never list talk chats. |
| `POST /api/chats {kind: "talk", text, model?}` | Makes a chat on its first send: `{id, title}`. `model` is one picked before the chat was made; a model that is not one line is refused with 400. Empty chats are never saved. |
| `PATCH /api/chats/{id} {model}` | The model the chat's next reply runs on. A live session gets `set_model`; a reply running now finishes on the old one. |
| `GET /api/chats/{id}` | The record; a chat carried over from an older build's terminal adds `earlier`, its words from Claude Code's session file (`~/.claude/projects/<folder>/<id>.jsonl`, text only, before the chat's first message here). |
| `POST /api/chat`, `/steer`, `/work`, `/approvals/{id}`, `POST /api/activity/abort` | As for a lesson ([one chat turn](05-one-chat-turn.md)). |

A chat's model is its record's `model` while its session is on the agent picked now (a pick made on the other agent names a model this one would refuse); with none, the model picked for the agent in Settings (`data/agent-folder.json` `model`); with neither, the agent's own default (`chat_model` in `app/agent_folder.rs`, which lessons use too). Jobs keep the agent's default. A chat turn runs beside a lesson's turn and beside jobs, each in its own session, and is not counted in the job pool. A chat's turn is also the teacher's round of work that Follow's slip shows ([8.1.2](08.1.2-the-teachers-round-and-the-strip.md#the-teachers-round-of-work)): its desk's steps go to the round as they are made, and the round ends with the turn.

#### The window (`src/frontend/components/teacher/`)

| Piece | What it does |
|---|---|
| `teacher-provider.tsx` | Owns the chats (`use-talk-chats.ts`) and the one the panel shows: the newest when the panel opens, else the one picked under Chats, just made, or waiting on a card. A card waiting in a chat opens the panel on it (`stepPanel`, after a typing pause) and lights the strip's "needs you". |
| `talk-chat.tsx` | `TalkChatView`. A new chat shows "Try asking" (`try-asking.tsx`: the page's lines from `startersFor`, and "All ideas", which unfolds every group in place); the first send makes the record and then sends. A chat reads its record, then runs on `useChatSession` and `useLessonServer` like a lesson, with the desk from `useDesk` (no paper in the panel): the teacher's words grow over it, its sentence folds away and its steps stay until the reply is finished. A line sent while the teacher works steers it. |
| `writing-row.tsx` | The lesson's box ("Ask anything", the attach glyph in its well), then Ideas once the chat is used, the model key, Stop while a reply runs, and Send, the main key only while the box holds something to send. Its words and files (`use-talk-box.ts`) are kept for the app run; a model picked for the next new chat is kept with them across a reload (`teacher-panel-next-model` in browser storage, with the agent it is for). |
| `use-thread-scroll.ts` | The thread at rest at its end when shown, and the glide that brings a sent line to the top. A card out of view gets one row pinned over the writing row; a click glides back to it. |
| `teacher-thread.tsx` | `TeacherThread`, shared with the cheat sheet's chat. The newest exchange gets a section as tall as the scrolling room, so a sent line glides to the top and the reply grows under it while the view holds still. |
| `talk-model.ts` | The thread's lines (earlier words first; steps and tool calls left out) and the error row's words: "Your message didn't go through." (Send sends again), "The app lost its connection to the reply." and "The reply stopped with an error." (both with Try again). |
| `model-key.tsx` | The chat's model by its name from the agent (`GET /api/agent/models`), a menu of the agent's models with the current one ticked. A new chat shows the model picked for it, else the one picked in Settings, else the agent's default, and sends its pick with its first message; a pick kept for the other agent is not shown or sent. Without a list the key is not drawn. |
| On a lesson or cheat sheet page | The page's own box is the one place to type (`boxPage`): the writing row gives way to "Type in the lesson's box." or "Type in the cheat sheet's box.", with Stop while a reply runs. The thread and its cards still work, and the box's words and files are kept for the app run. |
| Pop out | "Pop out" in the panel's head moves the chat to a window of its own (`chat-window.tsx`, on the shell's chat window); the panel closes. The window shows the same chat (`SHOWN_CHAT_KEY` in browser storage) with only "Put back" in its head. While it is open the panel is Activity alone. Put back closes the window and opens the panel on the chat the window showed. |
| Head (`panel-head.tsx`) | The teacher's name with a square that breathes while the teacher works anywhere; "Working" instead of the name while it works outside this chat (`workElsewhere`: the shown chat's own round and talk turns are left out). Keys in the top bar's look: Chats, Follow, Activity, Pop out. |
| Chats (`panel-chats.tsx`) | New chat, then the chats, each with its first line and how long ago it was used, the one shown marked "open now", and the agent's name when both agents have chats. |
