what godspeed keeps track of

where you're stuck

it checks what you know first, so it teaches the step you're actually missing.

one plan

the plan stays on screen and only changes when your answers say it should.

what you learned

every fact and every miss goes into your graph, and the next lesson starts from there.

how sure you were

you rate 1 to 5 on every answer, and topics you're overconfident on get flagged.

how it works.

while godspeed is open it runs an mcp server, and an agent you already use becomes the teacher. that same agent also does the background stuff, like research, diagrams, reading pdfs and building your knowledge graph.

no api keys. there's nowhere to paste one.

  • claude codeinstall the plugin, then /godspeed:teach
  • codexpaste one config snippet into config.toml
  • any mcp appconnect over streamable http with an address and a token

while you think, the claude code plugin just waits in a background script, so your agent spends zero tokens until you answer.

figures out where your understanding stops, from your answers, how sure you said you were, and what you typed while thinking.

bayshorescomputer science at uc san diego, class of 2028

i read a lot of ai explanations.
it wasn’t really working.

i'm taking cse 21 (discrete math) and cse 29 (systems programming in c) this fall. i kept notes in obsidian and asked claude or chatgpt whenever something didn't click.

i even wrote a tutoring skill so they'd give hints instead of answers. the replies got better, but every chat started from zero and the same confusion kept coming back days later. my obsidian notes had a confidence field on every concept. i never filled in a single one.

learnharness by amos blomqvist already taught the way i wanted to learn. it checks what you know, plans a path, teaches one step at a time, then makes you practice. but it needed api keys, and i only pay for subscriptions.

so i forked it. in godspeed the teacher is the agent you already pay for, and every class gets its own files, graph and exams.
